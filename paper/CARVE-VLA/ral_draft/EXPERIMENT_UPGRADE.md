# RA-L 实验补强：冻结方法与可证伪的双主张

更新：2026-09-24。本文件是下一轮实验协议草案，不是已完成结果。当前主稿中的 RoboMME 历史八任务结果属于开发/扩展研究；固定记忆确认只有 12 对，固定双任务 Raw/Harness 压力测试仅 `3/32 -> 4/32`，选择性规划在同链路质量门槛上失败。PyTorch PI0.5 的 `282.43 -> 54.67 ms` 是另一后端的单模型调用结果，不能和 RoboMME 的 JAX 闭环成绩相乘或合称全链路实时。

## 从参考论文借鉴什么

- [Harness VLA](../../Agentic%20Policy/Harness%20VLA.pdf) 的强项不只是模块多，而是固定 VLA checkpoint、同任务同初态的直接基线、任务特定记忆与部署评估分离、展示动作原语组合和长程操作；其论文跨 LIBERO/LIBERO-Pro、RoboCasa365、RoboTwin C2R。我们不必复制四个 benchmark，但至少需要一个**冻结版本、未参与调参的配对主结果**，并展示何时有收益、何时有伤害。
- [Agentic RAG-VLM](../../Agentic-RAG-VLM/main_final.pdf) 的实验图把视觉任务实例、推理机制和恢复结局连在一起。我们的图 1 因而采用真实任务输入、概念性记忆/策略插画和动作块时间轴；实验结果图仍由原始日志绘制，不能用生图补“成功例”。
- 图形工作流参考 [scientific-figure skill](https://github.com/happystander/codex-PaperFactory/blob/master/skills/scientific-figure/SKILL.md) 的 claim-first、source-manifest 和失败边界检查。`FIGURE_PROVENANCE.md` 标明各面板来自真实帧、生成插画还是方法示意。

## 要回答的三个问题

1. **Agentic 是否真的改善冻结 PI0.5 的长程任务完成率？** 主指标是官方 episode success，报告同初态的救回与伤害，而不是把一次内部 retry 算成独立成功。
2. **哪些模块带来收益或误干预？** 至少拆出无记忆 Harness 与有证据记忆 Harness；分析阶段判断、VLM 意图、工具执行及失败原因。动作块中途不能被语义判断改写。
3. **效率补偿是否在同一闭环中成立？** 对通过质量门槛的候选，报告整任务 wall time、Planner/VLA 调用、每次调用 P50/P95、峰值显存。当前 PyTorch 内核 profile 只能作独立补充，不能代替同链路比较。

## 紧凑的确认性设计

**冻结对象。** 固定代码 commit、GroundSG PI0.5 checkpoint、Qwen3-VL checkpoint、相机、16-step chunk、1300-step 上限、GPU 服务配置、prompt/tool schema、调用和恢复预算。每个任务先审计官方测试初态是否在开发期出现；有使用痕迹的 episode 不标作确认集。记忆只能从该任务允许的公开初始示教编译，不能从确认集的终局或失败回放构建。预先写出 task/episode/condition 列表及停止规则。

**任务而非堆 benchmark。** 先审计 `VideoRepick`（长期状态和重抓，历史 Raw `2/10`、Full `7/10`，但这只是选择任务的开发线索）作为预期收益任务；以 `PickHighlight`（历史有误干预）或 `VideoUnmask`（已知记忆负迁移）作为保护任务。`VideoUnmaskSwap` 的已有确认集只作机制和图示，不能重复作为新的独立确认。`RouteStick` 当前 Raw/Harness `0/16 -> 1/16` 接近地板，暂不作主任务；如审计后另有中等基线成功率且可观察恢复机会的任务，可在**看确认结果之前**替换。任务选择不以新跑出的 Agentic 成功例倒推。

**条件。** A：当前 GroundSG Raw 对照，即冻结 PI0.5 与其原有逐块 VLM 规划；它不是“纯 PI0.5”。B：同一 PI0.5/VLM 链 + Monitor、边界权限与受限工具，但无结构化任务记忆；C：B + 任务作用域、来源可追踪的记忆。D：C + 候选 Optimize Runtime，仅在独立保真和闭环质量准入后启用。A/B/C 的任务输入、初态、动作预算和终止规则必须一致。D 不得以提前失败换取短 wall time。若任务不允许相同任务输入/预算，差异单独列明。

**分两步运行。** 第一门槛在两个任务各做 8 个未用初态的 A/B/C 配对（48 回合），主要用于发现协议错误、基线地板和误干预；不得把这批数据挑选后再宣布显著。只有在至少一个目标任务同时出现真实可恢复事件和可观测的净救回、保护任务无明显新增伤害时，才以预先固定的 episode 列表扩至每任务至少 20 个配对初态。若已使用的 episode 过多，不能把重复初态伪装成新的留出集，必须换任务或明确标作复测。若门槛失败，停止扩样，回到故障归因，不转去挑更容易的 task 报好看数字。若面向 RA-L 主结果，还应在**事先指定的第三任务族**复制方向一致的结果；LIBERO-PRO 既有 40-task 对照作为广覆盖负/边界证据，不重复刷榜。D 的配对在 C 被固定且准入后进行，保持相同初态和服务条件。

**当前待审计候选初态。** 首轮预选 `VideoRepick` 与 `VideoUnmask` 各 ep38--45，不因结果好坏改选；它们在现存结果目录/索引中未见使用记录，但这还不是官方输入去重证明。运行前必须以 benchmark reset 生成公开示教、指令及首帧哈希，核对 16 个任务-episode 身份、各任务内部去重与记忆编译准入。若其中任一不合法，先记录排除理由并按事先设定的下一个合法 ID 顺延，不能看过模型结果后补种子。

**2026-09-24 预检结果。** 已在真实 RoboMME 容器中对上述 16 个测试 episode 执行官方历史模式 reset，并记录指令、公开示教哈希和首帧哈希；`artifacts/robomme/ral_gate_20260924/preflight_manifest.json` 的 16 项均通过重复首帧及现存 `summary.json` 检查。这只能排除本次可见文件中的重复，不能证明所有模拟状态都独立。公开示教的离线记忆编译中，`VideoUnmask` 8/8 通过容器跟踪门槛；`VideoRepick` 只有 ep41、ep45 同时通过目标选择和跟踪（2/8）。ep40 虽有连续跟踪，但目标选择 margin 为 0，必须拒绝；其余样本因跟踪丢失拒绝。不能把 `VideoRepick` 8 例都写成有效记忆处理，也不能只挑 ep41/45 宣称独立确认。后续 C 条件应对所有预选初态保留失败关闭的记忆回退，单独报告记忆准入率。另对 `VideoUnmaskSwap` ep38--45 做了仅示教预检，但全部 8 例都在旧 `summary.json` 中出现；进一步核查发现该任务 0--49 全部已用。因此它只能用于机制复测，不能充当新的留出主任务。小规模链路烟测选用此前预先列出的 `VideoRepick` ep41、`VideoUnmask` ep38；这两个有准入记忆的个例不得代替完整 8-pair 意向处理分析。

**报告。** 每个任务 × 条件公布 `success/n`、救回/伤害二元配对表、精确 McNemar 的探索性区间/检验、完成步数及双方都成功配对的 wall time/调用/显存；另报全回合成本，避免选择偏差。区分 VLM 触发次数、真正接受的子目标改动、调用技能次数、技能效果和安全拒绝次数。至少一组同初态成功救回、一组误干预/失败的视频与事件轨迹并排展示，标记它们是否来自开发集。负结果留在主文，不藏入附录。

## 本稿的止损线

如果冻结确认仍未显示目标任务的净救回，主张应收缩为“具身 Agentic 执行契约与误干预分析”，不能写系统提高总体成功率。若 D 在同链路质量或 wall time 上失败，只保留独立 PyTorch PI0.5 profile 与未通过准入的工程分析，不能写“Agentic + Optimize 同时更准更快”。当前稿件可以作为完整技术报告，但在这些确认结果出炉前，不应把它描述成已有 RA-L 级别的实验结论。

## 2026-09-24 实际运行补记：首轮不是正向成功率证据

固定初态 `VideoUnmask` ep38--45 的 A/B/C 配对已完成，机器生成的完整逐回合统计在 `artifacts/robomme/ral_gate_20260924/unmask_ep38_45_pilot_summary.json`，原始日志分别在 `smoke_rollouts_v6`（ep38）和 `unmask_ep39_45_abc`（ep39--45）。A 是 Raw GroundSG（同 PI0.5/VLM、每块规划），B 是无结构化任务记忆的观察式 Harness，C 是 B 加公开示教编译的身份记忆。三条件每组均检查相同初态哈希，记忆编译准入 8/8。
逐初态成败和条件性步数差由原始 JSON 生成，见 `figures/unmask_ep38_45_pilot_paired.pdf`；图中 ep43 的失败没有被画成“省 263 步”。

| 条件 | 成功 | 全回合平均步数 | 全回合平均 VLM/VLA 调用 | 全回合平均 wall time |
|---|---:|---:|---:|---:|
| A | 8/8 | 221.875 | 14.375 / 14.375 | 15.332 s |
| B | 8/8 | 221.875 | 14.375 / 14.375 | 15.370 s |
| C | 7/8 | 152.000 | 9.750 / 9.750 | 12.632 s |

全回合成本不能单独解释为效率增益，因为 C 在 ep43 提前失败。只看 A、C **双方成功** 的 7 个相同初态，中位 wall time 为 12.438→8.723 s，中位执行步数为 166→112；同时 ep39、ep40 的 C 并未更省步。C 相对 A 为 0 个救回、1 个伤害（ep43），探索性精确 McNemar `p=1.0`。ep43 在 144 步后 VLM 连续两次输出了问句而非可执行技能，触发 fail-closed；A/B 均完成。不能把这组数据写成“Agentic 提升任务成功率”，也不能忽略失效回合只报速度。

`VideoRepick` ep41 的初轮 A/B/C 均失败；C 起初在第 0 步受“历史坐标污染 + 模糊技能修复提示”阻断，而 A/B 均执行到 169 步。按日志定位后，已将该任务记忆提示改为经跟踪确认的**历史对象身份/相对关系**，不再注入历史动作坐标；格式修复也改为不含可被照抄的占位坐标。修复版 C 能执行到 217 步，但仍未完成任务，因此只能说接口可用，不能说性能改善。这个 ep41 已用于开发修复，不能作为新留出确认。`VideoRepick` 的其余 6 个预选初态记忆不满足准入，不能选择性只报 ep41/45。

这轮是**开发期小规模验证**：ep38 与后续 ep39--45 来自两个连续但源码哈希不同的运行目录，虽然后续修改只涉及 `VideoRepick` 记忆/技能提示，仍不应宣称为单一冻结提交的正式统计。若继续追求 RA-L，下一步优先解决“多目标阶段转换时 VLM 返回无效工具动作”的可复现错误：在块边界给出当前阶段的可验证执行收据、约束合法技能输出，并记录新旧方法在同初态上的救回与伤害。只有通过质量门槛后再进行优化运行时 D 的同链路配对；否则缩窄论文主张，不扩新 benchmark 掩盖问题。

## 2026-09-24 阶段切换修复与独立功能检查

针对 ep43 的问句回声，在 `scripts/run_robomme_vlm_groundsg.py` 中为 VideoUnmask 开放了显式选择的块边界阶段收据，并把无效技能修复提示限定为现有合法动作词表。收据只在第一目标的放置动作块确实执行后出现，记录夹爪重开状态，但不把重开等同于物体放置成功，也不在 VLA 动作块执行中途改写目标。`tests/test_robomme_execution_feedback.py` 的 54 项回归通过，包括问句不进入 VLA、修复后合法动作被接纳、两种 Unmask 任务共享收据约束。

已知失败 ep43 的**开发复测**保留相同初始观测哈希 `9160e37a...`、同 PI0.5/VLM 模型与 16 步动作块；旧 C 在 144 步遇到连续无效问句后停止，新 C 达到官方成功，共 365 步、23 次 VLM 与 23 次 VLA 调用。新轨迹在 144 步后没有触发修复重试，因此结果不能将收益单独归因于技能格式提示；它支持“边界阶段收据避免本例停机”的机制解释。原始结果在 `artifacts/robomme/ral_gate_20260924/unmask_ep43_stage_hint_dev/`。

随后对尚无既有结果的 ep46--49 先收集**仅公开示教**并预检，四例均通过可见旧结果和首帧去重；其中只有 ep47 含两个目标，按任务特征在看模型结果之前选作阶段切换检查。ep47 的 SAM2 记忆编译通过准入，A/B/C 三组同初态哈希 `0cd3d01d...`，分别为 Raw GroundSG、无记忆观察式 Harness、记忆加阶段收据 Harness。三组均成功；执行步数分别为 313/313/327，VLM 与 VLA 调用分别为 20/20/21，wall time 分别为 19.590/19.405/30.510 秒。C 在此例未提升成功率或效率。原始结果在 `artifacts/robomme/ral_gate_20260924/unmask_ep47_frozen_abc/`，预检在 `preflight_manifest_ep46_49.json`。

**当前结论：** 工程故障已定位并经目标回归和真实仿真复测；尚无足够的独立多目标配对样本证明此修复带来总体性能增益。ep43 不进入新确认集，ep47 只能作为一个新的功能验证样本。论文已按这个证据边界更新，不将单例复测写成泛化提升。
