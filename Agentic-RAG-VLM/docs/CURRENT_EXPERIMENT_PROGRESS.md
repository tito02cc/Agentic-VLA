# Agentic RAG-VLM 当前实验进展与答辩口径

更新日期：2026-09-10

## 1. 当前判断

目前已经形成两条互补的证据链：

1. **机制定量实验**回答“Agentic 模块是否真的带来增益”；
2. **VLABench 连续操作任务**回答“这些决策能否驱动机器人完成一条可见、连续、可验证的任务”。

因此，当前材料已经足以支撑中期答辩和面试中的项目演示。最合适的结论不是笼统地说
“抓取成功率 100%”，而是：

> Agentic RAG-VLM 能够把多模态模型给出的候选判断，转化为带有知识检索、空间约束、
> 任务记忆、在线纠错和结果验证的操作决策，并通过现成的 IK/技能执行层完成多阶段任务。

当前还没有完成 benchmark-wide 的多种子操作成功率和实机验证，所以不能把三条成功视频
外推成通用机器人成功率。

## 2. 已完成的证据

### A. Agentic 机制定量验证

正式 Challenge v4 使用 10 个冻结种子和 100 个方法 rollout，并在相同 seed 上进行配对比较。
它验证的是高层决策机制，不是把同一条机器人视频重复运行 100 次。

| 场景 | 被验证的能力 | Full Agent | 主要对照 | 对照结果 | 可直接得出的结论 |
|---|---|---:|---|---:|---|
| G1 | 可供性检索与手型路由 | 10/10 | VLM-only | 1/10 | 仅凭视觉直接猜抓法不稳定，检索证据能稳定手型选择 |
| G2 | 受保护关系到安全动作约束 | 10/10 | no-graph | 0/10 | 识别风险还不够，必须把空间关系转成可执行的方向与净空约束 |
| G3 | 变化归因、任务记忆与重规划 | 10/10 | no-memory / no-replan | 0/10 / 5/10 | memory 防止重复执行，replan 负责处理仍未完成目标的变化 |
| G4 | 检索、约束、变化与记忆的联合任务 | 10/10 | local / fixed skill | 0/10 / 1/10 | 单点能力不能替代完整闭环 |

配套证据：

- 246 次真实本地 Qwen3.5-4B 多模态调用，最终 endpoint error 为 0；
- 40 个 Full-Agent rollout 中执行 60 次 Agent 工具调用；
- 100 个运行目录和 260 个公开事件通过 public/private 隔离审计；
- G3 与 G4 均覆盖 `target_move`、`no_change`、`irrelevant_move`，Full Agent 的
  `false-replan=0`；
- 主要配对差异采用 McNemar exact 检验；Full Agent 的 10/10 对应 Wilson 95% CI
  `[0.72, 1.00]`。

这里最值得答辩展示的不是“10/10”本身，而是三个因果关系：

- 去掉 RAG，手型/抓法选择明显下降；
- 去掉场景图，模型即使说出了风险，也无法稳定生成正确动作约束；
- 去掉 memory 或 replan，系统会重复已完成步骤，或无法处理目标变化。

### B. VLABench 连续操作任务

当前选取了三个互补任务，而不是重复三次普通 pick-and-place。

| 任务 | 完整动作链 | Agentic RAG-VLM 的可见作用 | 结果 |
|---|---|---|---|
| 化学配制 | 取 HCl → 对准烧瓶并倾倒 → 取 NaOH → 对准并倾倒 | 反应知识检索、顺序约束、玻璃容器姿态约束、管口对准验证 | benchmark 与严格 Agentic 目标判据通过；第二支试管安全收尾待补 |
| 家庭烹饪 | 识别候选食材 → 依次取 broccoli 与 cheese → 放入盘中 | 配方 RAG 排除 fish，任务记忆确认两个子目标均完成 | benchmark 与严格 Agentic 验证均通过 |
| 健康冷饮 | 开冰箱 → 重观测 → 选饮料 → 取出并放置 → 关冰箱 | 保留 VLM 的 Monster 误判，由意图 RAG 纠正为 juice，再做结果验证 | benchmark 与严格 Agentic 验证均通过 |

三条主展示轨迹的执行层统计：

| 任务 | 原速时长 | IK 调用 | 插值事件 | IK/关节跳变/物理门禁 |
|---|---:|---:|---:|---:|
| 化学配制 seed 5 | 44.4 s | 405/405 接受 | 18 | 0 |
| 家庭烹饪 seed 7 | 33.9 s | 304/304 接受 | 0 | 0 |
| 健康冷饮 seed 0 | 50.8 s | 457/457 接受 | 7 | 0 |
| **合计** | **129.1 s** | **1,166/1,166 接受** | **25** | **0** |

“低层由 VLABench 技能执行”的准确含义是：任务级 Agent 选择目标、顺序、约束和纠错策略；
技能层把笛卡尔航点转换成 Franka 的 7 关节目标，并由控制器执行。它是 IK 驱动的低层执行器，
不是另一个 VLA 在替 Agent 完成高层推理。

### C. 执行可靠性与审计

为避免“高层答案正确，但动作本身不可信”，执行器已经加入：

- 仅对 7 个机械臂关节求解，避免手指关节参与末端位姿补偿；
- IK 收敛、关节限位和有限值检查；
- 对较大的合法关节变化进行插值；
- 非法目标、过大关节跳变或 MuJoCo 物理异常时拒绝继续执行；
- 每次调用、重试、插值和门禁结果写入 `result.json`。

这能支持“所展示轨迹通过了执行质量检查”，但不能被表述为“任意场景都不会碰撞”或
“已经完成真实机器人安全认证”。

当前化学 seed 5 还记录到一次与 `HCl_tag` 相关的异常接触力代理值，正在按标签碰撞几何或
接触分类问题排查。因此“物理失稳门禁为 0”只能说明轨迹未因 `PhysicsError` 中止，不能表述成
“全程无碰撞”。该问题应在最终视频强化安全结论前完成复核。

此外，化学 planner receipt 规划了 20 个技能并要求两支试管归位；canonical 轨迹在 NaOH 第二次
正向倾倒达到 benchmark success 后只执行到第 14 个 stage，后续撤离、回正、归位和松手没有进入
视频。因此当前可说“反应目标和严格管口判据完成”，不能说“20 个技能全部执行”或“第二支试管
已经归位”。这与 `HCl_tag` 一起是交接后的 P0 修复项。

### D. 保留的失败与负结果

- 化学 seed 0：第二支试管未成功离开槽位，L3 重抓仍失败，保留为恢复能力边界；
- `find_unseen_object`：VLABench 柜体/抽屉资产会在开启动作中弹出目标物，未作为成功证据；
- 早期人形机器人 URDF 接触动力学没有达到主展示标准，不再作为当前的核心抓取视频。

这些结果不放在主视频中，但在被追问“是否只挑成功案例”时可以主动说明：系统保留失败日志，
且未把 benchmark 物理异常或未完成接触抓取包装成成功。

## 3. 当前 84 秒答辩视频

新的 VLABench 总览视频工程已经完成，时长 84 秒，包含：

1. 方法与低层执行器的边界；
2. 化学任务中的顺序、姿态和管口对准；
3. 烹饪任务中的配方检索与干扰物过滤；
4. 冷饮任务中的真实 VLM 误判、RAG 纠正和闭环验证；
5. 三任务的统一结果收束。

制作阶段已运行 HyperFrames 的 lint、runtime、layout、motion 和 contrast 检查，并保留了
视觉快照；目录中没有持久化机器可读 check report，所以正式渲染前应再运行一次 strict check。
当前状态是 **composition 与视觉快照完成、尚未渲染最终 MP4**。主视频将三条完整源轨迹
等比例加速，没有删除中间操作步骤；答辩被追问时可以切换到三条原速视频。

## 4. PPT 建议结构

### 第 1 页：问题与方法

标题：**Agentic RAG-VLM：让视觉候选变成可验证的机器人决策**

只讲三个问题：经验误检索、空间/语义约束缺失、失败后难以恢复。

### 第 2 页：系统边界

`RGB-D → VLM Planner/Router → RAG/Scene Graph/Memory → Skill/IK → Verify/Replan`

一句话说明：Agent 负责“做什么、为什么、需要什么约束、失败后怎么办”；IK/技能层负责
“如何把目标位姿变成关节动作”。

### 第 3 页：100 个方法 rollout 的固定种子配对实验

只展示 G1–G4 的 Full 与主要对照表。结论依次说成：

1. RAG 稳定抓法选择；
2. 场景图把风险变成动作约束；
3. memory + replan 让系统只纠正尚未完成的目标；
4. 联合任务需要完整闭环。

246 次模型调用、260 个公开事件和 60 次工具调用放在页脚作为可信度证据，不要在台上逐项念。

### 第 4 页：三组连续任务

以三列展示化学、烹饪和健康冷饮。每列只保留“任务难点—Agent 决策—最终验证”三行。
现场播放 84 秒视频。

### 第 5 页：重点案例——健康冷饮

单独放出这条决策链：

`Fridge closed → Open → Re-observe → raw VLM: Monster → intent RAG: Juice → Pick/Place → Close → Verify`

这是最能体现框架独立价值的案例，因为原始模型输出和最终执行决策被明确分离，纠错不是靠
剪视频隐藏错误。

### 第 6 页：结论与下一步

结论：**框架的价值不是替代低层控制，而是给低层执行器提供可解释、可约束、可纠错的任务级决策。**

下一步只列两项：

1. 对三个 VLABench 任务扩展 5–10 个种子，并增加 VLM+skills、RAG-only、Full Agent 的
   任务级成功率对比；
2. 在相同 Agent 接口下接入真实机器人执行器，推进 sim-to-real。

## 5. 答辩中的推荐表述

### 30 秒版本

“我们把 Agentic RAG-VLM 实现成一个任务级机器人智能体。它先从 RGB-D 中形成候选判断，
再通过可供性知识、空间关系和任务记忆决定抓什么、怎么抓、需要避开什么，以及场景变化后
是否重规划。机制层完成了 10 个冻结种子、100 个方法 rollout 的固定种子配对实验；操作层在 VLABench 完成化学
配制、家庭烹饪和开冰箱取健康饮料三条连续任务。其中冰箱任务保留了模型把 Monster 误判为
健康饮料的原始输出，并由意图 RAG 纠正为 juice，最后完成取出、放置、关门和结果验证。”

### 一句话结果

**定量消融证明各 Agent 模块为什么有效，三条连续任务证明这些决策能够真正落到机器人操作。**

## 6. 可以讲与不应讲

| 可以讲 | 不应讲 |
|---|---|
| 100 个方法 rollout 的固定种子配对设计验证高层机制贡献 | 100 次完整物理抓取均成功 |
| 三条完整 VLABench 任务均通过 benchmark 与 Agentic 验证 | Agentic RAG-VLM 在整个 VLABench 达到 100% 成功率 |
| 三条主视频累计 1,166 次 IK 调用全部接受 | IK 接受等于所有接触均物理真实或绝对安全 |
| 健康冷饮包含真实在线 VLM 误判与 RAG 纠正 | 所有三条视频都使用同一个模型配置 |
| 已验证框架可与现成 IK/技能执行器组合 | 已完成端到端 VLA 训练或实机 sim-to-real |
