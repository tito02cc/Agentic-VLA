## 受约束视觉进展门控

自然成功/失败视频被用于一个不含 reward、success label 或对象真值的离线语义门控。
Qwen3.5-4B 的统一 NF4 配置把可见成功轨迹误判为停滞，未通过语义准入。保留视觉
编码器 BF16、仅量化语言解码器后，模型正确提取了失败 `3 -> 3` 和成功 `3 -> 1`
的可见对象组数，但自由生成的 `status` 字段仍与其数值证据矛盾。

基于这一结果，Harness 先新增 `ScalarVisualPredicate`，随后进一步改为更保守的
group-enumeration 协议：VLM 只返回 `visible/groups/confidence`，Harness 以列表长度
计算观测值并执行确定性比较。这样避免模型同时输出相互矛盾的数值、证据和状态。

门控：3 个自然失败帧均输出 3 组，3 个自然成功帧均输出 1 组；平均单次时延约
1.86 秒。该模型与 StarVLA、Isaac Sim 在 RTX 4090 上完成同卡共驻，并在真实在线
回合中完成 3 次视觉检查。量化 VLM 因此满足可运行性和语义准入要求，但当前瓶颈
已经从“能否发现停滞”转为“恢复工具能否改变策略行为”。

## 语义子目标与后段门控复核（2026-09-02）

针对“对象数量不变但 VLA 持续执行”的自然失败，框架加入受约束的 VLM Planner。
Planner 只能输出保持原任务操作词、引用当前视觉 Critic 已观测实例的高层子目标；
低层关节、末端执行器或力矩指令会被 Guard 拒绝。重复对象任务还要求使用
`left/right/center` 等实例限定词。所有语义子目标均为临时指导，并在两次成功 VLA
调用后自动恢复原始任务指令，失败的 VLA 调用不消耗指导预算。

连续机制试验给出了以下边界：

| 版本 | 触发与行为 | 官方结果 | 结论 |
|---|---|---:|---|
| v5 | 第 512 步改写为自由语义子目标，指导持续至回合结束 | 0/1，score 0 | 持久改写会破坏原任务契约 |
| v6 | 第 512 步触发，子目标仅持续 2 次 VLA 调用 | 0/1，score 0 | 有界指导解决状态泄漏，但未改善该轨迹 |
| v7 | 320 步为 3 组、640 步为 2 组，检测到真实进展而不干预 | 0/1，score 0 | 仅依赖停滞会错过“有进展但到期未完成” |
| v10 | 320 步为 3 组、640 步为 1 组，后段门控不干预 | 1/1，670 帧 | Critic 与官方成功一致，避免了过早干预 |

v10 的官方成功不能写成恢复增益，因为本回合没有执行语义恢复。它证明的是门控的
非干扰正例：VLM 只提供动作无关的可见进展证据，Harness 保留控制权，RoboDojo
evaluator 仍是唯一成功判据。完整视频、两次 Critic 原始输出、Runtime/Monitor trace、
`summary.json` 与校验和位于
`artifacts/robodojo/paired_v10_stack_bowls_c2_deadline_grounded_seed2_20260902/`。

同日的 C1 名义等价配置出现一次成功（score 100），而两次 B0 为 score 15；但不同
启动回合的首个动作块哈希并不一致。StarVLA PI-v3 的 flow-matching action head 会由
`torch.randn` 采样初始动作噪声，单纯固定环境/服务种子不足以形成逐轨迹配对。因此
该 C1 个案暂不归因于 Runtime，也不进入因果结论。

框架现已加入可选的请求级 `action_seed`：服务端在隔离 RNG 上下文中生成动作噪声，
并在调用结束后恢复全局 RNG；实验启动器按 `base_seed + env_id + chunk_timestep`
生成种子。官方未设置该字段时行为保持不变。后续 B0/C1/C2/C3 必须先通过动作哈希
复现门控，再进入多回合统计。

## 任务启动计划与确定性视觉门禁（2026-09-02）

针对只在失败后生成单个局部提示的局限，框架加入任务启动计划：VLM 在首帧提出
有限阶段计划，Harness 将其编译为单调任务账本；阶段只可按视觉证据依次确认，
每阶段最多重试两次，预算耗尽后恢复原始任务。三碗堆叠计划被约束为两个语义阶段，
不得拆成接近、抓取、移动等低层运动步骤。

VLM 准入结果显示了清晰的模型分工边界：

- Qwen3-VL-2B vision-preserving NF4 无法稳定生成满足两阶段和实例定位约束的计划，
  因此只作为在线视觉 Critic，不承担高层 Planner。
- Qwen3-VL-4B vision-preserving NF4 在真实首帧上一次通过计划门禁，离线耗时
  `21.16 s`；在线 shadow 经一次 schema 修复后通过，总耗时 `35.76 s`。
- 4B Planner、StarVLA 与 Isaac Sim 同卡执行在首个 VLA 请求发生 OOM。因此 4090
  上采用“4B 分阶段计划票据 + 2B 在线视觉验证”，不能表述为 4B 在线共驻规划。

首个执行回合暴露出 Critic 自相矛盾：其标签为 `confirmed`，证据却写明
“left and center bowls are not stacked”。该回合立即停止，不计入结果。框架随后
加入状态与证据一致性门禁，并把三碗堆叠阶段改为确定性组数谓词：VLM 只枚举可见
组，Harness 根据 `3 -> 2 -> 1` 判定阶段。第二个诊断回合又发现三相机导致同一对象
被重复枚举，故计数谓词固定只使用主相机；腕部视角不参与跨视角计数。

修复后的 v20 回合在官方 `stack_bowls`、layout 0、seed 2 上完整运行：

| 项目 | 结果 |
|---|---:|
| 官方结果 | `1/1`，452 帧 |
| VLA 调用 | 27 次 |
| VLA P50 / P95 | `307.00 / 346.13 ms` |
| 在线 2B Critic | 2 次，`2.52 / 2.34 s` |
| 阶段证据 | 两次均为 3 个独立碗组 |
| Harness 行为 | 重试第一阶段一次，随后按预算回退原任务 |
| Recovery compute | 2 次 h32 调用 |

最终成功发生在回退原始任务之后。该回合证明计划安装、证据提取、确定性裁决、有限
重试、保守回退与官方成功视频的完整闭环，但不能声称局部任务分解导致成功。视频还
显示两次局部提示均未形成预期的部分堆叠，提示冻结的 RoboDojo StarVLA checkpoint
未必支持分布外子目标语言。

因此 Adapter 新增 `carve_vla_instruction_capability`：

2. 语义调用预算耗尽曾被错误映射为安全停止；现改为继续原始 VLA，不再停机。
3. Critic 的语义观察/重规划权限与停机权限现已分离。停机权限默认关闭，只有任务级

4. 高层 Planner 的输出被 Guard 拒绝时，旧路径可能执行其 fail-closed 停止意图；现改为
   保持原动作块和原任务，并熔断本回合 Planner。合法的 Planner 停止请求同样受上述
   显式权限控制。
5. 高层 Planner/Critic 的事件触发观测由单头部相机扩展为头部和双腕三视角，不增加
   调用频率，只提高遮挡条件下的语义证据覆盖。

## 在线任务台账机制门与验证协议加固（2026-09-02）

首先运行 `task_only` 条件下仅依赖本地 `ExecutionRiskMonitor` 触发 Planner 的
`stack_bowls` 回合。机器人持续运动但对象状态没有语义进展，Monitor 未产生事件，在线
Planner 调用数为 0，官方结果为失败。该结果证明仅靠关节、动作变化和时序等低成本信号
无法覆盖“仍在运动但任务停滞”的语义异常，因此停止重复该触发方式。

随后接入任务开始时的在线 Qwen3-VL-4B Planner。三视角输入生成两阶段计划：先堆叠

`task_only`，因此 Planner 只维护阶段目标和检查时机，不向冻结 VLA 注入未经验证的开放
子目标。首次计划耗时约 `7.57 s`，进一步确认 VLM 只能低频事件触发。

该回合在 160、320、480 步执行三次阶段检查，经过连续两次矛盾门控后刷新动作块一次，

801 帧）。视频显示三只碗最终靠近但未形成堆叠，不能作为性能提升样本。

运行同时暴露出 grouped verifier 的协议漏洞：4B 模型返回

## 单卡语义后端资源边界（2026-09-02）

视觉保留 NF4 Qwen3-VL-4B 与 StarVLA、RoboDojo 同卡共驻时在首次策略推理 OOM，该
运行已标记为排除，不进入实验分母。进一步测试对全部线性层（含视觉编码器）使用 NF4：
静态已分配显存为 `2.71 GiB`，视觉推理时约 `3.70 GiB`，但固定 48 样本门控的终态
召回从视觉保留 NF4 的 `3/8` 降至 `1/8`；因此该 profile 被正式拒绝，不能为节省显存
而用于在线视觉 Planner/Critic。

当前部署结论是：RTX 4090 可稳定运行 RoboDojo + StarVLA，以及不常驻独立 VLM 的
Monitor/回放恢复；独立 4B VLM 的完整在线 C3 应使用远端服务、第二 GPU 或显式分阶段
调度。不能把一次勉强成功的共驻回合写成稳定单卡部署能力。拒绝证据位于
`artifacts/robodojo/critic_admission_v1_20260902/qwen3vl4b_uniform_nf4_results.json` 和
`qwen3vl4b_uniform_nf4_admission.json`；两次 OOM 目录均保留 `RUN_NOTE.md`。
