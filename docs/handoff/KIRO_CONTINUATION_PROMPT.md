### 3. 当前真实执行路径

RoboDojo是当前主要开发平台。使用官方ARX-X5环境，StarVLA负责加载已有PI-v3
task-trained动作checkpoint，本地Qwen3-VL-4B BF16负责语义Critic/Planner。
StarVLA是模型接入工具，不是我们用别人的系统替代了自己的Harness。

真实入口在：

`third_party/robodojo_official/XPolicyLab/policy/starVLA/model.py`

主链路包括观察、低成本执行监测、有预算的VLM判断、指令能力门控、恢复动作执行、
动作边界之后的新观察核验、回合状态清理和日志。

当前RoboDojo动作模型使用task-only约束，保留原任务文本。Planner提出自由文本
子目标不等于动作模型能够执行它。当前恢复主要是原任务下的动作块重规划及受限
计算/执行预算，不要宣称已经具备任意新物理技能。

模型生成50步chunk，当前常用执行前16步。旧请求中的`num_ddim_steps=10`曾被
忽略，实际原生默认是4个flow steps。以生效配置与metadata为准，不凭请求字段猜测。
现有stack_bowls对照没有支持flow2作为默认配置，应以flow4作为下一步保真起点。
这不是永远禁止少步优化，而是需要新的闭环准入证据。

此外还有可选应用路径：FastAPI、LangGraph、Gateway/Session、CanonicalToolRuntime、
SQLite回执。它有独立软件测试，但尚不能将现有RoboDojo视频视为HTTP链路全程实跑。
你可以选择是否统一两条路径，也可以保留清楚的适配边界。不要为“统一”强行重写
成熟模型后端，判断标准是降低真实维护成本、保证实验行为与清楚说明能力。

### 4. 框架能力与真实缺口

Monitor是高频、低成本的执行信号监测器，VLM Critic/Planner是低频语义模块。
Harness拥有工具权限和预算，VLA负责连续动作。这些职责都需要保留清楚。
我重视真正的Agent能力，不接受仅用规则触发器就宣称完整语义智能。
同样，不要为了“像Agent”让VLM每步调用或任意执行未经验证的动作。

已有任务账本、受约束工具、恢复后核验、过程记录、参考对象记忆与可信程序接口。
但当前RoboDojo自然任务中，在线多阶段计划、主动长期记忆与稳定对象身份收益尚未
充分验证。软件里有接口、真实模型调用、任务效果提升是三个不同层次。

恢复完成后要等实际动作执行边界，再取得新观察核验，不能拿恢复前图像自证成功。
`confirmed / contradicted / inconclusive`必须如实保留，模型输出合法JSON不等于
物理结果正确。现有通用post-check问整个任务是否完成，未决不证明局部恢复没有帮助。
局部后置条件是一个值得研究的方向，但你应判断如何设计，不只是照抄这一建议。

可信程序必须有来源、适用域和验证记录。任务日志不是自动学得的新技能。
历史LIBERO程序建立使用过官方任务评估信号作离线晋升依据，不能包装成无监督学习。
目前没有完成自主微调、多智能体技能训练或真机部署；老师的建议是长期参考，不是已有成果。

### 6. 已有结果，必须保持准确

**LIBERO/LIBERO-PRO历史矩阵**

四套本地suite，每任务前10个官方状态，三个方法共1,200回合。
Frozen 180/400，Fixed 181/400，Agentic 183/400。
Agentic增加0.75个百分点，失败转成功4、成功转失败1，McNemar p=0.375。
控制步少7.2%、VLA调用少8.4%，但回合wall time多16.5%。
不等于大幅提升成功率，也不等于整体提速。

**RoboMME历史八任务合并子集**

Raw 23/80，Harness 36/80，Full 42/80，总240回合。
Full相对Harness的Planner调用少40.6%，wall time少28.1%。
Raw本身包含Planner，不是裸VLA。合并来源包含开发和扩展块，多个开发版本目录，
不是新的单次统一冻结确认性测试。开发40任务回合为5/16/22成功，扩展40为18/20/20。
汇总算术可追溯，但不能用p值替代选择过程审计。

**PI0.5独立推理**

RTX 4090上7步Eager P95 282.43 ms，2步Compile+SMVE P95 54.67 ms，降80.6%。
45个记录观测的保真阈值检查使用相同候选步数参考，不是7步降2步无损证明。
SMVE仅消除契约声明为无效的静态相机计算，不是随意剪掉有效相机。
P95是样本95百分位，不是硬实时保证。

**量化**

Qwen3.5-4B NF4已分配显存8.46→3.08 GiB，但P95约1.90→2.91秒。
