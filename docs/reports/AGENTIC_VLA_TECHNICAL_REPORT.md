### 0.1 先给结论：完成了什么，卡在哪里

项目不是只有设计图：通用Agent会话、工具执行、任务账本、过程记忆、执行监测、
VLM调用及优化配置管理都有实现；历史LIBERO/RoboMME也有真实闭环与效率结果。
但是，**最新两个RoboDojo任务尚未验证完整自主Agent的任务收益**，不能描述成
“框架没有任何缺口，只剩把benchmark跑完”。当前主要缺口不是再加一个模块名称，
而是两条能力连接：**视觉证据能否支持可靠核验，以及高层决策能否变成有效动作**。

RoboDojo分支采用官方RoboDojo π0.5，不再把之前的StarVLA PI-v3称为当前主后端。
整理桌面与语言分类的原生模型各跑完一个真实仿真回合；另外完成一个人工固定子指令
诊断回合。三个回合均不是完整Agent新方案的实验，也均未达到官方整任务成功条件。
后续有多个受限Agent开发回合；最近一回合为工具返回修复后的75分，仍未完成整任务。
这些是不同配置下的开发记录，不能合并成独立成功率样本或把25→75归因于单项修复。
本报告将通用代码、历史实证、新后端开发诊断分开陈述，历史失败和正结果全部保留。

### 0.2 我们到底在构建什么

可以把系统理解为：**VLM提出计划与判断，Harness管理执行权与状态，VLA生成动作，
Runtime管理调用成本；动作执行后的新观察再用于检查，而不是相信模型自己说成功。**

```text
任务指令 + 三路RGB + 机器人关节状态
                  |
          Agentic Harness / Session
          |       |                |
       任务账本  工作记忆      工具权限与预算
          |                        |
          +--> VLM Planner --> 受校验的任务/工具建议
          |                        |
          |                  统一工具执行接口
          |                 /       |        \
          |             VLA动作   重新观察    停止
          |                |
          |       模型适配与 Optimize Runtime
          |       [仅启用该后端验证过的配置]
          |                |
          |          动作块 -> 仿真机器人
          |                |
          +<-- 新观察 <-----+
                |          |
      Monitor: 执行信号   VLM Critic: 语义核验
                +----------+
                 继续 / 重规划 / 有限重试 / 停止
```

这是逻辑架构，不表示所有箭头已在最新两任务中共同完成真实运行。
新π0.5驱动已有受限组合实跑，但Critic确认权与自由子目标执行未准入；新VLA后端的
模型级Optimize尚未启用。4B VLM的NF4部署已用于实际回合，不等于VLA也已量化。
通用FastAPI/LangGraph外部Agent入口是另一条接入路径，不能把当前视频说成其全链路演示。

### 0.3 每个部分分别负责什么

| 部分 | 输入、职责与输出 | 当前边界 |
|---|---|---|
| VLM Planner | 看任务、RGB、历史与工具清单，提出步骤、调用意图、恢复建议 | 当前4B已通过两份初始计划的有限目标覆盖检查；不等于物体定位或动作可执行 |
| ExecutionRiskMonitor | 用关节响应、动作目标误差、图像变化等信号发现执行异常 | 程序判据，不是独立模型；不知道“是不是把手表放对篮子” |
| VLM Critic | 用新RGB和预期结果判断confirmed/contradicted/inconclusive | 与Planner职责独立，但可共用同一模型；当前有高置信误确认 |
| Harness / Session | 校验建议、约束工具权限、保存进度、预算、回执，处理失败与过期返回 | 不是另一个基础模型；是把模型建议转成受约束执行的程序层 |
| VLA | 图像、语言、机器人状态进入模型，输出连续动作块 | 没有因为加入Harness就自动学会新动作或任意子指令 |
| Memory | 保存观察、假设、任务进展与有来源的经验 | 最新工作记忆不是可靠物体追踪器，也不是自动技能学习 |
| Optimize Runtime | 管理模型接口、生效参数、性能记录、候选优化与回退 | 算法/后端必须逐项验证，旧PyTorch速度不能套到新JAX模型 |

“有界恢复”就是重试次数、工具次数、任务控制步数都有上限，越界后停止或报告失败。
它不是“保证恢复成功”。同步仿真里的暂停也不是经过认证的实机安全控制器。

### 0.5 一次任务如何执行：代码流程与实际验证分开

1. 接收原始任务和公开观察，建立本回合独立的工作区、预算、账本；不读取仿真器隐藏物体标签作为决策输入。
2. Planner给出计划。程序检查格式、任务条款是否遗漏、分类目的地是否改错，并保留原始模型输出。
3. task_only模式下，账本可以管理语义阶段，但VLA仍接收完整原指令；“有阶段计划”不等于动作模型正在执行独立子目标。
4. VLA生成动作块，驱动逐步执行；Monitor发现事件时中断剩余旧动作，获取新观察后再请求后续动作。
5. 周期或事件触发语义检查。Critic检查当前目标，必要时复查已确认阶段；发现矛盾可重新打开该阶段及依赖工作。
6. Planner可继续、请求重新观察或提出其他受支持意图。失败、超时、预算耗尽不会无限循环。
7. 官方evaluator独立计算最后得分和成功；账本“完成”不能代替官方任务成功。

这是`SortingEpisode`的已实现流程。最新整理桌面回合每100步复核，并在工具返回后
即时重新规划；Planner实际选择continue与reobserve，不允许Critic确认阶段，也不开放
任意子目标动作权限。因此工程反馈闭环已有证据，但完整自主纠错与语义阶段推进尚未
验证。语言分类尚无这套新驱动的Agent整回合。

### 0.6 工具与记忆：已有的和还没有的

通用工具接口支持观察、记忆检索、VLA动作、注册技能、核验与停止。
当前排序适配器默认`run_skill`提供 **reobserve**：保持当前关节目标一个控制步，
重新获取观察。可显式开放候选 **feedback_refresh**：执行短VLA前缀后获取反馈；
最新回合开放了候选，但Planner没有选它，不能写成其效果已验证。两者均不保证抓取
纠偏、抬升重抓或指定物体抓取，也不是任意Python控制机器人。
因此，高层即使诊断出“拿错物体”，目前也没有已验证的专用纠正工具可保证执行该建议。

9月21日追加的独立`proposal_review_smoke`提供 **execute_prefix_10/50**：先读原VLA
动作及robot-only FK摘要，再消费同一份已经生成的提案，无额外VLA调用。真实Planner
已两次选50步；短前缀/停止的路由有软件测试，但本轮没有相应真实选择，也没有纠错
收益。另有目视准入的毫米级运动诊断，不作为Planner生产工具。详见13.33--13.34。

| 记忆种类 | 已有内容 | 不应混淆为 |
|---|---|---|
| 任务账本 | 阶段、尝试、确认、撤销与依赖关系 | 模型写一句“完成”就成为事实 |
| 当前工作记忆 | 最近6张缩小头部图、最多12条模型笔记及24条执行回执；每回合重置；新默认将模型笔记隔离于决策检索之外，保留可核查回执 | 稳定对象ID、向量RAG、完整长视频理解、跨回合学习 |
| 恢复记录 | 已做过什么、用掉多少次预算、结果如何 | 新动作技能的训练数据闭环已实现 |
| 可信程序记忆 | 历史有限LIBERO任务上有验证后程序复用实验 | 当前RoboDojo已自动发现技能并持续学习 |

模型笔记明确标记为未验证假设；最新代码默认不让历史笔记进入决策上下文，当前Critic
仍是独立、带时间的未验证建议。隔离本身不能修复Critic错误，且尚无新物理回合收益。
HAA-RAG、Scene Graph来自前期工作的思路和可复用模块，不能宣称全部在当前新路径启用。
老师建议的“记忆 + 长程执行 + 高效推理”与现有主线一致；“多智能体自动微调技能”
目前是更远的研究选项，不是已经完成的能力，也不是这轮仿真必须先加入的前置条件。

### 0.7 高效推理到底做到了哪里

高效推理包含三种不同目标：减少一次调用的计算、减少不必要调用、降低联合部署显存。
三者需要分别度量，不能只看模型参数量或单次延迟。

| 方法 | 通俗解释 | 已有证据与当前限制 |
|---|---|---|
| 少步动作生成 | 减少flow迭代次数 | 旧PI0.5有校准和小规模闭环；新官方π0.5仍保留10步 |
| 编译与预热 | 减少执行框架开销，避免把首次编译算作稳态 | 旧PyTorch路径有实测；不等同JAX端已经复现相同优化 |
| SMVE | 不计算被明确屏蔽的填充视角 | 只适用于存在这类无效输入的路径；新模型三路真实相机不能直接删 |
| 选择性Planner调用 | 状态没有必要重判时，不重复调用昂贵VLM | RoboMME历史对照支持减少调用和总耗时；新两任务尚未验证 |
| 低比特量化 | 用低比特表示部分权重以节省显存 | 新4B VLM加载占用8.266→3.268GiB；最新完整回合整卡10秒采样最高23814MiB（约23.26GiB）；非瞬时峰值，未证明语义等价或加速 |
| 权重驻留/CPU副本 | 让VLM与VLA轮流使用显存时减少重复搬运 | 旧PI-v3路径有切换测试；不是新JAX部署已验证配置 |

P95是调用延迟的第95百分位：约95%的测量调用不超过该值。
它不是每次调用的最大时间，不包含所有系统开销时也不能叫整机响应时间，更不是硬实时保证。
当前没有本路径的FP8 KV Cache、蒸馏、剪枝或新量化内核实证；不需要为显得完整而写入成果。

### 0.9 为什么选这两个任务，是否值得继续

整理桌面包含多个对象、目的地和操作，适合检查阶段覆盖、已经做过的操作是否保持、

暂保留两个预先选定任务，不因看到失败就删除分类或换容易任务充作原实验成功。
优先在固定观察上解决核验、在明确动作接口上解决可执行性，再扩大真实回合。

## 摘要

本项目研究在预训练视觉语言动作模型（Vision-Language-Action Model，VLA）之外，
构建能够管理任务状态、调用具身工具、利用过程记忆、监督执行并进行有预算恢复的
多模态智能体系统，同时优化视觉语言模型（Vision-Language Model，VLM）与VLA
协作时的计算与部署成本。系统由两个主要部分组成：Agentic Harness通过执行信号
监测、低频语义判断、类型化工具、权限校验和动作后核验组织闭环；Optimize Runtime
通过统一模型契约、推理配置、动作保真度检查、资源调度和分项计量，管理模型推理效率。
两者不是分别提高“智能”和“速度”的独立插件，而是在同一个执行生命周期中共享
观测新鲜度、动作能力、调用预算、恢复边界与可回退配置。

历史LIBERO/LIBERO-PRO四套本地suite共1200回合中，Agentic相对原始模型的成功数
由180/400变为183/400，差异不显著；VLA调用减少8.4%，但总回合耗时增加16.5%，
揭示了低层调用减少不等于整体推理加速。RoboMME八任务开发/扩展汇总共240回合，
Raw、Harness、Harness加选择性调度分别成功23/80、36/80、42/80；完整系统相对
每动作块调用Planner的Harness减少40.6%的Planner调用和28.1%的总回合耗时。
这一结果限于该任务子集及历史配置，不是全部RoboMME或全新统一冻结测试的成绩。

模型层面，PI0.5离线调用P95由7步eager配置的282.43ms降至2步编译与静态无效视角
消除配置的54.67ms；45个观察上的后端保真检查是相同推理步数下的阈值检查，不代表
7步到2步逐位无损。量化实验显示显存与延迟可能相互制约，部分INT8组合虽通过离线
保真仍在闭环失败，因而未获得组合准入。

9月14日及以前的RoboDojo路径采用预训练QwenPI-v3与本地Qwen3-VL-4B，已集成受限恢复及
动作结束后的新观测核验。最近四条件、每条件两个stack_bowls回合成功数为2/2、
0/2、1/2、1/2，说明工程闭环运行成功但不能宣称稳定任务收益。补充固定真实输入
重放在12个样本上验证了flow4包装路径的执行动作前缀逐位一致；6个输入上的模型
切换验证也保持输出。冻结权重CPU副本把测试提示下完整语义调用中位耗时由约
16.3--16.9秒降至5.1--5.3秒，代价是约17.712GiB主机副本内存。当前成果支持一个
具备真实仿真与部署测量依据的具身智能体研究原型；上述配置不等于最新部署。

9月15日起的主线改为官方RoboDojo π0.5/JAX与整理桌面、语言分类两个任务。
原生模型各一个开发回合得分75/100和0/100，均未整任务成功；人工手表分类子指令
另跑一回合，没有验证正确类别/目的地执行。4B VLM的初始计划覆盖检查有进展，
但BF16与NF4 Critic都在同一个初始观察上误确认鼠标已摆放，因此暂不能自动确认完成。
当前两个新任务没有自主Agent闭环收益或新后端加速结果；开放任务规划、RoboDojo
长期记忆主动收益、硬实时与真机验证仍需进一步工作。

最新整理桌面受限Agent回合在原π0.5与原场景上得75分、未成功，真实验证一次
“重新观察、执行回执进入记忆、即时重新规划”的工具返回链。后续目标无关视觉检查
在12组配对中减少了特定负例的错误定位接受，却误拒绝一张清晰图并增加2.87倍累计
VLM调用成本，因此未接入生产执行。这些结果将下一阶段明确为可靠语义核验与有效
动作纠正能力的联合验证，而不是扩大缺乏收益依据的重复回合。

## 1. 研究动机与问题定义

### 1.1 为什么在VLA外部增加智能体系统

VLA给定图像、语言与机器人状态后输出动作，但一次动作调用本身不提供完整的软件
运行机制：当前任务进行到哪里、上次尝试是否完成、何时值得重试、是否应该调用更贵
的模型、失败后保存哪些经验，都需要外部系统维护。模型可能具备一定隐式推理能力，
但这不等于其接口直接暴露了任务账本、工具权限和可审计恢复语义。

本研究不以“冻结VLA优于微调VLA”为命题。模型训练与系统组织解决不同问题：
前者扩展动作能力和分布适配，后者管理已有能力的调用、反馈、成本及错误边界。
冻结预训练checkpoint便于隔离系统改进，也符合单台4090的工程资源条件。
若模型根本不会某种动作，Harness无法只靠重试和自然语言凭空创造该技能。

### 1.2 为什么Agentic系统需要推理优化

高层VLM引入新的成本：多帧/多轮token、图像编码、规划和验证生成、重复判断、
VLM/VLA共享显存时的权重搬运，以及等待期间的动作过期。一次局部错误恢复也可能
需要Critic、Planner、VLA和后置核验多次调用。因此必须同时回答：

1. 是否做了对任务有用的推理？
2. 是否在合适时机调用？
3. 同样的推理能否用更少资源完成？
4. 优化是否改变了动作和最终行为？

### 1.3 研究问题

- RQ1：如何组织可替换VLM/VLA之间的规划、工具执行、核验和恢复闭环？
- RQ2：如何区分执行信号异常与语义失败，避免误触发和无限重试？
- RQ3：如何使记忆有来源、能失效、可复用，而不是把错误模型描述当成事实？
- RQ4：如何分别降低高层调用次数、动作模型推理开销和模型切换成本？
- RQ5：如何用可复现实验区分工程接通、语义正确、局部恢复和整体性能收益？

### 1.4 前期成果与外部参考的关系

Agentic RAG-VLM是已有工作，提供可供性感知检索、场景关系约束及自反思规划思路；
对应材料完整保留在 `paper/Agentic-RAG-VLM/`。当前报告不重新核查其录用状态或
复述其全部实验，也不将其成绩记入CARVE-VLA。

Harness VLA/RPent是工具生态与持续控制思想的参考。可复用的是模型之外的工具边界、
执行反馈、过程记录和无基座训练评估思路，不是复制其成功率或宣称自己的模块首创。
参考仓库位于 `third_party/RPent/`，论文位于 `paper/Agentic Policy/`。
本文是本项目技术底稿，不是截至某日全面检索的最新文献综述；“新颖性领先”仍需独立论证。

## 2. 总体系统设计

### 2.1 四层职责

```text
任务指令、当前观察、历史上下文
                 |
知识与语义层：VLM Critic/Planner、结构化检索、任务与观察记忆
                 | 类型化建议，不直接下发任意动作
Agentic Harness：状态机、工具权限、预算、时序、核验与恢复
                 | 通过能力检查的执行请求
Optimize Runtime：模型适配、部署配置、推理/资源管理、计量与回退
                 | 合法动作块
环境/机器人适配：执行动作、返回观察；独立评估器记录任务结果
                 +------------反馈至Harness/语义层
```

这是一套接口设计，不表示每个backend都具备所有功能。具体模型需要声明精度、
推理步数、动作长度、语言指令能力和观测/动作语义；缺失能力不能靠统一字段假装存在。

### 2.2 三种频率不等于三路并行

执行监测可以逐控制步运行，VLA按动作块生成，VLM只在任务边界或事件时低频运行。
这是调用频率与职责分离。历史RoboDojo PI-v3单卡staged路径在VLM调用时顺序卸载VLA、
加载/运行VLM、再恢复VLA，属于串行等待；不能称VLM永远不阻塞动作关键路径。
通用异步Planner接口的存在也不代表这条具体部署路径实现并发实时控制。

### 2.3 三条接入路径必须分开画

| 路径 | 实际组成 | 验证状态 |
|---|---|---|
| 历史RoboDojo PI-v3路径 | 官方evaluator -> StarVLA桥接 -> 项目Monitor/VLM/Runtime/恢复核验 -> VLA动作 | 有真实模型、仿真、日志与视频；非当前主后端 |
| 当前RoboDojo官方π0.5路径 | AgenticPi05入口 -> SortingEpisode -> Session/工具 -> π0.5适配与真实仿真端口 | 原生和受限Agent回合已运行；最新工具返回链通过，Critic可靠性、纠错收益和新后端优化待验证 |
| 可选外部Agent应用路径 | FastAPI -> LangGraph请求流程 -> Gateway -> Session -> CanonicalToolRuntime -> 绑定的执行器 | 有应用契约测试，未把当前RoboDojo视频作为此HTTP链的全链路验证 |

历史RoboDojo入口在 `third_party/robodojo_official/XPolicyLab/policy/starVLA/model.py`。
当前新入口在 `third_party/robodojo_official/XPolicyLab/policy/AgenticPi05/model.py`，
核心驱动在 `agentic_vla/benchmarks/robodojo_pi05_episode.py`。
通用会话与工具接口在 `agentic_vla/session.py`、`external_agent.py`、`toolchain/`。
三条路径复用概念和若干部件，但不能称已合并并共同完成验证。新排序驱动明确拒绝
external_coding_agent模式；不能把通用外部Agent API等同于此驱动已经接上云端编码Agent。

## 3. 模型契约与可替换性

### 3.1 统一观测和动作请求

用说明性记号表示：

\[
o_t=(I_t^{1:K},q_t),\quad A_t=\pi_\theta(o_t,g_t;\epsilon_t,p_t),
\]

其中图像为 \(I\)，机器人状态为 \(q\)，任务或已准入指令为 \(g\)，随机噪声为
\(\epsilon\)，部署配置为 \(p\)。动作块 \(A_t\in\mathbb{R}^{H\times d}\)。
这是接口抽象，不是新增学习目标；本项目没有以该式训练一个新基座模型。

`InferenceRequest`携带观测、指令、episode/timestep、request_id及推理控制；
`InferenceControls`包含inference_steps、max_actions、precision、reuse_context、deadline_ms。
`ActionChunk`记录动作、模型耗时和元信息。`max_actions`是执行输出截断，不等于减少
模型原生生成长度；历史PI-v3可输出50步，相关实验实际执行前16步。
新官方π0.5原生基线使用50步动作块，不能混用两者调用次数。

### 3.2 动作语义是跨模型适配的必要条件

`ActionSpec`显式规定动作维度、表示、坐标系、夹爪约定、控制频率、归一化与边界。
从单臂增量末端动作到双臂关节目标，不能只改数组长度。Monitor的动作变化、端点误差、
夹爪一致性也必须按动作表示解释。通用接口降低接入成本，不消除机器人语义适配成本。

### 3.3 原生能力与生效参数

`ModelCapabilities`声明是否支持动作分块、配置推理步数、KV缓存、不确定性等。
一项优化必须被adapter/backend支持且有明确生效回执，不能只凭请求参数作统计。
原生PI-v3旧payload曾包含 `num_ddim_steps=10`，实际实现读取 `num_inference_steps`，
忽略旧键后使用checkpoint默认4步。新增trace因此记录请求值与生效值，并将动作解码
描述为flow matching，不再误记为10步DDIM推理。

### 3.4 task-only与开放子目标能力

当前RoboDojo checkpoint按原任务使用。Planner可以输出建议，但能力路由保留原任务
文本，不将自由生成子目标直接下发。此时Agent能控制重新观察、动作块重规划、
有限恢复预算与核验，不能承诺任意语言组合都能执行。
RoboMME GroundSG策略则使用其适配好的grounded subgoal接口；两者不是相同能力。
“模型可替换”应表述为统一适配协议，而不是所有VLA已经即插即用、无需适配且效果一致。

## 4. Agentic Harness方法

本节描述共享设计及历史PI-v3桥接生命周期；160步/320步调度、12秒恢复期限等
属于该历史路径，不是新排序驱动的默认参数。新驱动参数和工具限制见0.4--0.6节。

### 4.1 执行风险监测

`ExecutionRiskMonitor`用可部署信号计算动作命令大小、相邻状态响应与图像变化，
维护滑动窗口。说明性地可写为：

\[
c_t=\|u_t\|,\quad s_t=\|q_t-q_{t-1}\|,\quad
v_t=\operatorname{mean}|I_t-I_{t-1}|/\text{scale}.
\]

当命令存在而状态/视觉响应很低时产生stall候选；当命令、响应都低且持续较久时
产生no_progress候选。另记录动作年龄、不确定性和deadline余量，形成风险分数与事件。
这些量是诊断信号，不是任务完成分类器。低运动可能是正常等待，视觉变化也可能来自
相机/光照；阈值必须结合具体adapter的动作量纲和自然失败数据校准。

### 4.2 VLM Critic与Planner

Critic输入当前图像、任务、预期结果或可观察谓词，返回已满足、未满足或不确定。
Planner在需要时接收事件、有限记忆、任务阶段和可用意图，提出结构化建议。
两者职责可以由同一checkpoint承担，但请求语义不同，不能把一次Planner输出当作
动作之后的独立核验。

系统依次检查协议合法性、置信度/预算、观测新鲜度和VLA能力。合法JSON不等于
空间关系判断正确；低置信、超期、无法辨认的结果保留unknown/inconclusive。
当前恢复核验为新观察上的独立调用，但通常仍是同一个VLM，因此仍可能存在相关错误，
不等同使用了独立真值裁判。

### 4.3 语义调度与停滞证据

最新调度分开维护：上次周期检查、上次实际检查、上次计入停滞证据的观察、连续
未变化的起始步。调用预算、计数间隔和未变化跨度共同决定是否允许恢复。

\[
\text{stall candidate}=\text{valid observation}\land
n_{\mathrm{unchanged}}\ge n_{\min}\land
(t-t_{\mathrm{start}})\ge S_{\min}.
\]

这是当前程序判据的概括，不是学得的策略。相隔160步的两次观察只覆盖160步；
要求320步跨度意味着至少第三次名义观察，不能写成与旧“两次检查”规则等价。
强制检查可以即时看现场，但仍记账；过近观察不能制造更多停滞证据，发现变化则要
切断旧计数。未知、拒绝、完成以及恢复发起会中断旧停滞链。
同一步重复调用或倒序检查在最新桥接代码中被拒绝，避免重复花费预算。

### 4.4 七类工具与执行权限

| 工具 | 作用 | 副作用和约束 |
|---|---|---|
| observe | 获取当前可部署观察 | 只读；旧回执不能当新观察 |
| retrieve_memory | 取有限经验或过程上下文 | 只读检索，不赋予模型任意数据库写权限 |
| vla_act | 请求已准入模型产生一个动作块 | 检查episode、能力、动作规格和安全边界 |
| run_skill | 执行已注册的有界技能 | 必须存在于当前adapter白名单；不是任意代码执行 |
| verify | 核验预期结果 | 模型报告、物理证据和官方评分分开保存 |
| safe_hold | 进入adapter定义的保持状态 | 需要生命周期、超时及恢复策略，不是硬件安全认证 |
| finish | 结束并保存状态 | 工具完成不自动等于任务成功 |

工具词汇统一，但某个后端可以不提供某些物理技能。不能把其他平台的retract/lift
支持，描述成当前RoboDojo已验证同样的恢复动作。

### 4.5 任务账本与恢复状态机

`EmbodiedTaskPlan`维护pending、active、retry_required、confirmed阶段；
禁止跳过未确认工作，避免模型仅在文本中声称完成。9月14日PI-v3开发矩阵未启用
在线多阶段计划；新排序驱动已接入账本并运行受限Agent整回合，但Critic仅为建议，
账本未确认阶段。回合完整执行和相关代码/测试不是长期规划效果的证明。

一次恢复的生命周期为：

```text
执行事件 -> VLM建议 -> 能力/预算检查 -> 创建待核验恢复
    -> 生成动作块 -> 等最后一块真实执行完 -> 接收新观察
    -> 后置核验 -> confirmed / contradicted / inconclusive
    -> 记录结果、继续原任务或依约停止
```

`RecoveryVerificationLifecycle`记录开始步、观测序号、图像摘要、预期结果及
最后动作块结束位置。生成动作不等于执行动作；只有跨过实际执行边界且得到新观察
才核验。待核验期间不叠加同类恢复；预算耗尽、超期或结束时未验证都要保留状态。
当前12秒期限是返回后的有效性检查，不是强制取消GPU推理的硬截止保证。

最新已运行协议的通用后置检查问整个任务是否可见完成，因此未确认不代表局部恢复
毫无帮助。后续可以定义更局部的预期后置条件，但需要真实语义验证，不能只改提示词
后就把结果标成恢复成功。

### 4.6 闭环执行伪代码

下列是对接口与生命周期的说明性归纳，不是声称所有backend运行同一个完整函数。
在线多阶段计划与可信程序晋升没有在当前两任务完成闭环效果验证；启用前须单独准入。

```text
reset(episode, generation):
    清理本回合的触发证据、预算、待核验恢复与动作上下文
    仅保留具备适用域和验证来源的跨任务记忆

on_observation(observation, executed_step):
    校验episode、generation、step和动作/观察规格
    更新低成本执行信号；处理已实际执行动作的回执

    if 存在待核验恢复 and 动作边界已跨过 and 收到新观察:
        独立请求post-check；检查有效性与预算
        记录confirmed / contradicted / inconclusive
        不以工具调用成功自动宣布任务完成

    if 到达检查点或执行风险事件 and 时序/调用预算允许:
        调用VLM Critic，解析语义结果
        unknown / 拒绝 / 进展变化 -> 清理旧停滞证据
        有效无变化 -> 按最小间隔累积证据

        if 持续跨度、置信度、能力和恢复预算均满足:
            请求Planner建议并进行工具权限检查
            创建恢复尝试；使用准入profile执行有界动作块
            等待未来实际执行边界与新观察，不立即写成功记忆

    if 契约失效或预算策略要求停止:
        按adapter执行保持/停止并记录原因
    else:
        由准入VLA配置生成动作，执行允许的前缀并保存trace
```

这里的“控制者”是带状态和权限的Harness，语义判断由VLM提供，具体连续动作由VLA
提供。三者各自承担可检验职责，既不是纯VLM自由控制，也不是把规则Monitor称作VLM。

### 4.7 正常执行保护：观察不等于干预授权

9月22日结合用户真机工程观察与10.4开发结果，将低侵入执行作为后续设计约束。
用户反馈不当作本项目已完成的真机对照。Harness的价值应是维持任务状态、处理有依据
的阶段切换和恢复，而不是频繁替代VLA控制接近、抓取、搬运的中间步骤。

三个边界不能混淆：推理/动作前缀结束允许更新控制输入；chunk结束允许复核但不
证明操作完成；语义阶段交接还需要适用的后置条件、失败核验或显式目标/预算事件。
“保持目标”也不是保持旧动作：VLA仍正常使用新观察，移动目标的像素定位需刷新。
操作粒度遵循已适配checkpoint，不能把整任务模型和GroundSG分步策略强行统一拆解。

建议的职责为：Monitor发出观察证据和复核请求，VLM提出语义判断，Harness检验边界/
证据/预算后才准入普通修改；可信危险由独立机器人安全控制处理。不等待LLM推理才能
急停，也不把通用Agent工具标成硬件安全系统。细化协议见主计划AM。

本轮代码只补齐一个实际缺口：通用session在`at_safe_boundary=false`时，普通Planner
结果不再先写任务账本、再被工具权限拒绝；现在在任何这类更新之前拒绝应用并记录。
SAFE_STOP不经过该普通修改门禁。工具注册器已有单操作互斥，补测并发调用被拒绝。
注意：软件`safe_hold`本身也受工具锁约束，不能抢占活跃VLA；真实急停需独立部署通道。

跨多个chunk的技能承诺、阶段交接准入和跨步异步建议的有效性仍待实现与闭环验证。
本次未新增GPU或真机回合，通用session改动不计入10.4直接runner的六组已完成实验。

## 5. 记忆系统与研究承接

### 5.1 五种记忆的边界

| 类型 | 内容 | 生命周期与信任来源 |
|---|---|---|
| 任务账本 | 顺序阶段、当前阶段、尝试和核验 | 单任务；由Harness推进而非任意模型改写 |
| 过程/失败记忆 | 事件、尝试、结果、未决原因 | 回合隔离；日志不是自动学得的新技能 |
| 观察/参考记忆 | 来源图、裁剪、标签、框、时间与哈希 | 有效期/来源/重置控制；标签仍是模型假设 |
| 过程技能记忆 | 可复用符号步骤、约束、适用条件 | 经明确来源验证后保存，不直接存任意动作串 |
| 服务请求账本 | request_id、请求指纹、pending/completed/indeterminate、回执 | 持久化防重复；不是语义记忆 |

### 5.2 从Agentic RAG-VLM继承什么

HAA-RAG（Hierarchical Affordance-Aware Retrieval-Augmented Generation）按类别、
可供性/物理属性与视觉相关性组织操作经验。场景关系约束描述容器内容、碰撞、支撑
和遮挡，反思机制区分参数调整、方法切换和重新规划。这些是知识层的研究承接。

当前系统把知识影响限定为任务上下文、符号步骤、约束或注册技能选择，而非允许
检索内容直接输出任意关节向量。并非所有当前RoboDojo配置都启用了HAA-RAG和场景图；
论文中若画完整设计，需标记可选知识层而不是宣称本轮成绩由其贡献。

### 5.3 过程记忆如何进入执行与效率优化

经过验证的过程可在相似任务启动时提供符号计划，省去重复规划；较小模型可承担
已知过程中的核验，而不必每次调用较大Planner。这样记忆同时影响任务组织和计算路由。

`VerifiedProcedureCompiler`要求任务级确认和来源，筛选成功的符号过程；若需要
语义核验则不能只凭工具返回成功晋升。验证源可以是机器人侧检测、人工或评估器，
信任来自调用者和记录来源，不是类型系统自动证明现实正确。
历史LIBERO T3记忆建立使用过私有评估器任务成功作离线晋升依据：不得描述为全程
无外部监督的自主学习。在线Planner没有直接读到评估器状态，与离线验证用标签是两回事。

### 5.4 当前RoboDojo对象记忆限制

已有来源明确的参考全图/对象裁剪与失效控制，也试验过定位、跟踪和重新观察。
但层间对象身份仍可能混淆，增加候选框数量不能当作准确率提高。参考模式默认关闭或
只读shadow，未准入定位驱动动作。因此长期记忆是重要的已实现研究方向，但不能把
历史RoboMME/LIBERO收益直接移植为当前RoboDojo主动记忆收益。

## 6. Optimize Runtime方法

### 6.1 三类优化对象

1. **模型调用内部**：编译、推理步数、静态无效输入消除、组件级精度选择。
2. **模型之间**：驻留/切换、权重搬运、显存与主机内存分配。
3. **Agent调用流程**：选择性Planner调用、有效上下文复用、记忆路由和请求去重。

三者可以组合，但独立通过不代表组合通过；必须重新检查输出、任务质量和资源成本。
减少flow步数不是量化，CPU副本不是模型压缩，调用次数减少不是单次kernel加速。

### 6.2 Profile与部署准入

`OptimizationProfile`描述backend、精度、组件范围、推理步数、动作长度和选项；
`ProfileManifest`绑定模型/adapter、软硬件版本、保真、测速、闭环与回退证据。
可用说明性判据概括：

\[
\operatorname{admit}(p)=C_{\mathrm{contract}}\land C_{\mathrm{fidelity}}
\land C_{\mathrm{latency/memory}}\land C_{\mathrm{closed-loop}}.
\]

具体门槛依实验与adapter配置，代码中的admission是证据策略，不是性能的数学保证。
研究报告的“不准入”也不一定自动覆盖所有旧launcher默认值，实际启动仍需显式配置
和能力检查。没有证据的候选不能仅因配置文件存在就称可部署。

### 6.3 编译与静态无效视角消除

PI0.5编译后端使用 `torch.compile` 优化动作采样执行，固定步数路径便于减少
Python和图调度开销；需要记录预热/编译与稳态时间，不能把启动成本从所有场景忽略。

SMVE（Static Masked-View Elision）跳过adapter契约声明为无效padding的静态相机
输入。在对应LIBERO接口中，某个视角掩码全为false，优化才允许去掉相应编码工作。
它不是按模型置信度随意丢弃真实相机，不适用于没有这种静态冗余的输入；同样需后端
保真验证，不能只根据“被mask”推断全模型计算必然逐位相等。

### 6.4 动作保真而非纯语言指标

比较同一真实观察、指令、固定噪声和动作区间的参考/候选输出：

\[
\mathrm{MAE}=\frac{1}{Hd}\sum_{h,j}|A^{p}_{h,j}-A^{ref}_{h,j}|.
\]

现有检查包括首动作MAE、整块MAE/RMSE、余弦相似度、夹爪符号一致性及累积差异代理。
**必须按实现解释单位**：通用 `endpoint_l2` 是前几个动作通道累加差的范数，不经过
机器人正运动学，不能写成厘米级末端位置误差；`jerk_rmse` 当前实现是动作序列二阶
离散差之差的RMSE，不含真实时间标定，不能直接称物理jerk。双臂关节模型须使用适配
后的指标；当前PI-v3重放主要报告实际执行前缀逐元素差异。

阈值通过意味着样本内满足预设容差，**不等于逐位一致**，也不保证闭环成功率不降。
本报告对PI-v3的12/12使用“逐位一致”，对PI0.5的45/45只使用“阈值检查通过”。

### 6.5 角色/组件相关量化

VLM低精度误差可能改变语义/工具意图；VLA误差会沿连续动作积累，二者分别校准。
VLM实验比较BF16、INT8、NF4；NF4是特定4位权重编码，不应一律标作普通整数INT4。
PI0.5先对语言早/中/晚层和视觉编码器分组做INT8敏感性试验，保护动作专家及投影等
敏感通道。已有后端以TorchAO等工具实现量化，本项目贡献在组件选择、动作质量门控
和系统组合验证，不宣称发明了底层量化格式或通用CUDA量化kernel。

### 6.6 冻结权重CPU副本与单卡切换

普通staged过程：VLA从GPU移到CPU -> VLM上GPU生成 -> VLM回CPU -> VLA回GPU。
对于不更新的权重，重复把相同权重从GPU拷回CPU浪费时间。
`FrozenParameterCpuMirror`为冻结参数保留一份CPU副本；卸载时切回主机副本，
激活时从副本上传。buffer仍按当前状态搬运，不能假定推理过程所有张量都不变。

该模式要求冻结、eval、普通连续参数，并检查身份、版本与配置变化；训练、
自动dispatch、compile、量化包装不能未经适配直接使用。同卡切换需要串行化。
代价包括常驻CPU副本、主机内存压力、仍存在的上传和生成耗时；不是免费降低总内存。
当前六输入对照的完整语义调用仍约5秒，因此必须与低频调度配合，不能称高频实时VLM。

### 6.7 时效、复用与真实控制边界

动作/上下文复用要绑定episode、观测、阶段、模型profile及事件；reset、目标改变、
风险或过期时失效。通用框架有异步Planner及复用接口，但应单独验证具体backend。
当前结果没有证明新型real-time chunking或硬实时流式动作在RoboDojo全面启用。
达到某次模型调用80ms门槛与满足传感、通信、控制时钟的端到端实时要求不同。

### 6.8 成本分解与实时性解释

对当前串行部署，可以用说明性成本分解定位瓶颈：

\[
T_{episode}=T_{env}+T_{io}+\sum_i T_{VLA,i}
+\sum_j(T_{switch,j}+T_{VLM,j})+T_{other}.
\]

分项必须按不重叠的计时区间定义；若VLM调用计时已含权重切换，就不能再次相加。
异步或流水线部署存在重叠，此加法式也不再是直接的wall-time计算公式。
选择性调度减少求和项数，编译/少步推理改变单次VLA成本，CPU镜像减少切换成本；
这些优化作用不同，应分别消融。

若控制周期为`dt`、尚可执行缓冲为`h`步，则`h * dt`可作为推理等待预算的一个参考，
但只有策略允许执行已有动作、缓冲未过期且部署确实并行时，才能用它讨论遮蔽等待。
当前staged RoboDojo并未证明这一条件，不可由“输出16步”推断VLM数秒等待已被隐藏。
观测年龄、动作生成年龄与控制期限也要分别记录；离线P95低于80 ms只是一个配置门槛。

## 7. 软件Agent应用层与工程可靠性

应用层实现FastAPI认证、严格请求schema、LangGraph单次工具请求图和SQLite回执。
请求含request_id、episode_id、timestep、工具名与参数；同ID同内容返回历史回执，
同ID不同内容拒绝。一个未决派发会阻止新的有风险执行，避免客户端重试重复动作。

数据库和物理动作不能原子提交：动作完成而回执尚未落盘时进程可能崩溃。
因此采用pending/indeterminate保守处理，而非宣称物理动作exactly-once。
服务默认限制执行权限，动作工具仍受Session和Harness门控；外部Agent不能通过HTTP
传任意shell、模型路径或原始动作向量。

LangGraph在这里组织 `admit -> dispatch -> persist_receipt`，不等于已经实现自主
多智能体学习，也不是整个机器人状态的可恢复checkpoint。此层为求职提供真实服务化
代码与测试，不能因使用了某框架库而声称机器人能力提高。

## 8. 实验设计、统计与测量口径

### 8.1 分层实验逻辑

| 层次 | 问题 | 证据 |
|---|---|---|
| 软件契约 | 状态、预算、权限、reset是否正确 | 单元/集成测试；可使用测试替身，但不算机器人实验 |
| 同输入模型重放 | 包装/量化/切换是否改变输出，耗时多少 | 真实记录payload、固定噪声、分项计时 |
| 真实仿真集成 | 真实模型是否驱动动作，恢复与核验是否发生 | 官方环境、视频、执行回执 |
| 有限机制对照 | 某个模块对局部任务/恢复有何影响 | 声明条件、自然或受控故障、全部成功失败 |
| 跨任务评估 | 是否在独立任务/布局上提高质量与效率 | 冻结配置、独立重复、方差和统计、负结果 |

### 8.2 成功、干预和时间

- 成功率由官方评估器或明确独立标准决定，不以VLM自述替代。
- VLM调用、接受的建议、真正控制干预、已执行恢复和核验确认分别计数。
- 多条日志记录同一动作按generation/env/step/action去重，不能重复算干预。
- 模型时间、Runtime时间、模型切换、任务wall time、进程总时长分别报告。
- P50是样本中位数，P95是95百分位；小样本P95尾部不稳定，不写成最大响应保证。
- 视频的25fps或20fps是编码播放速率，不代表包含VLM等待的wall time。
- checkpoint磁盘大小、模型已分配显存、峰值显存、进程显存、RSS与CPU副本大小不能混用。

### 8.3 配对统计与局限

对于固定任务/episode的二元结局，记录失败转成功 \(b\) 与成功转失败 \(c\)，
配对差为 \((b-c)/N\)。精确McNemar检验基于不一致对，不把大量双方都失败的回合
误当有效救回样本。bootstrap/Wilson区间沿用来源协议，合并统计不能消除开发集选择
或任务内相关性问题。多任务多次调参后再报告p值，应说明其探索性。

RoboDojo初始RGB在同布局/种子下仍有小幅差异，但不意味着benchmark不可运行。
可以做按任务/布局分块、平衡条件顺序、多个独立重复；不能由一对不同结局声称因果
恢复。像素差异与渲染数值非确定性相符，但目前不足以断言唯一根因或排除全部因素。

### 8.4 各实验不能相互替代

LIBERO历史恢复、RoboMME grounded工具规划、当前RoboDojo task-only控制有不同能力
边界。下文保留各自checkpoint、任务、样本量和baseline定义；B0/B1/C1/C2/C3是局部
条件名，不跨表推断相同实现。所有冻结结果保持原样，不以新版代码覆盖旧结局。

## 9. LIBERO-PRO：恢复与执行成本的历史对照

### 9.1 设置与对照

数据来源为[E01汇总](../../results/libero_pro_full_study_20260825/aggregate/study_summary.json)。
本地协议选取`libero_10`、`libero_10_object`、`libero_10_swap`、`libero_10_task`四组，
每组10个任务，每任务10个初始状态；每个方法400回合，三个方法共1,200回合。
其中标准LIBERO-10承担原分布对照，其余为接入的LIBERO-PRO变体。
这不是官方所有任务、所有初始状态的完整排行榜评估。

- Frozen：预训练VLA直接执行，不调用高层VLM。
- Fixed：使用固定恢复逻辑，不调用高层VLM。
- Agentic：在执行监测与恢复基础上加入VLM语义判断；具体以冻结协议为准。

同任务和前10个官方初始状态配对，未进行模型微调。固定动作模型为PI0.5 LIBERO
PyTorch checkpoint，BF16、2步推理、horizon 10、静态无效视角配置，VLA截止线80 ms；
Agentic语义模型为本地Qwen3.5-4B，每回合最多一次有界笛卡尔恢复。
因此Frozen在此表示未增加Agent能力，不表示它是本报告11节的7步Eager配置。
完整协议见[历史设置说明](../status/LIBERO_PRO_FULL_STUDY_RESULTS_20260826.md)，
每任务行和每方法结果保留在来源JSON中，不与RoboDojo的PI-v3模型混写。

### 9.2 总体结果

| 条件 | 成功/回合 | 成功率 | 控制步总数 | VLA调用总数 | 回合wall time合计/s | VLM调用 |
|---|---:|---:|---:|---:|---:|---:|
| Frozen | 180/400 | 45.00% | 159,651 | 16,047 | 7,610.69 | 0 |
| Fixed | 181/400 | 45.25% | 145,586 | 14,442 | 7,296.35 | 0 |
| Agentic | 183/400 | 45.75% | 148,103 | 14,699 | 8,864.60 | 263 |

Agentic相对Frozen增加0.75个百分点，不是3个百分点，也不是显著大幅提高：
配对失败转成功4次、成功转失败1次，精确McNemar双侧`p=0.375`。
控制步减少7.23%，VLA调用减少8.40%，但回合wall time合计增加16.48%。
这说明减少动作调用并不自动抵消VLM调用成本，是后续调度与模型驻留优化的直接动机。

Agentic记录173个含恢复的回合、84次安全停止，恢复回合中24个最终成功。
“恢复后成功24次”不能写成“救回24个失败”：只有与对照配对的4个失败转成功
才是对应结局差异，而且小样本仍不足以单独证明因果。

### 9.3 可支持的结论

1. 恢复和停止机制在真实仿真中可执行，能够改变行为和执行成本。
2. 当前配置在该协议下的总体成功率收益较小，不能据此宣传通用鲁棒性显著提升。
3. Agent语义调用的时间开销真实存在，必须与VLA加速共同评估。
4. 早停减少步数可能来自及时终止，也可能来自放弃本可成功的任务，不能只以步数少判断好坏。

本次技术报告重新求和核对了40个任务条目与总成功数，没有重新运行1,200回合。
历史原始视频和审计结论按原有归档保存；本次没有重新解码逐帧复核全部历史视频。

## 11. PI0.5与VLM：高效推理和量化

### 11.1 PI0.5独立优化矩阵

来源为[E03效率汇总](../../results/carve_efficiency_full_20260826/summary.json)。
使用RTX 4090、`pi05_libero_pytorch`、45个记录观测、固定噪声、执行horizon 10、
80 ms推理截止线。离线样本、模型后端、预热和统计口径按各原始profile记录。

| 配置 | 推理步数 | Runtime P50/ms | Runtime P95/ms | 峰值已分配显存/GiB | 超80 ms比例 |

| V1 Eager BF16 | 2 | 147.13 | 151.35 | 7.12 | 100% |
| V2 Compile BF16 | 2 | 63.77 | 66.06 | 6.98 | 0% |

参考输出比较；脚本会把候选步数应用到参考调用。它不是7步→2步无损的证明。
V0/V1是参考路径，保真样本数为0，不能写成它们也完成45次独立保真测试。

### 11.3 Planner精度与显存权衡

同一E03中的Planner独立实验使用**Qwen3.5-4B**，不是当前RoboDojo使用的
Qwen3-VL-4B。30组配对的`temporal_code_v5`请求比较如下：

| 条件 | 已分配显存/GiB | P95/ms | 样本内决策一致 | 定位 |
|---|---:|---:|---:|---|
| BF16 | 8.46 | 1,896.55 | 30/30 | 延迟优先参考 |
| INT8 | 4.84 | 6,504.45 | 30/30 | 当前kernel不适合延迟目标 |
| NF4 | 3.08 | 2,909.79 | 30/30 | 低显存候选 |

NF4相对BF16已分配显存减少63.63%，P95增加53.43%。协议合法率与样本内决策一致率
均为100%，但30个请求不能证明任意复杂场景的语义质量不变。
NF4是4-bit量化格式，不应笼统写为“INT4整数推理”；当前报告也没有FP8 KV Cache
实测证据。量化相关贡献应写为分角色配置、敏感区域保护与准入验证，而非声称发明
了NF4、INT8或通用量化算法。

### 11.4 “轻量化”到底完成了什么

已完成的是：VLA组件量化探索、VLM低显存配置验证、无效视觉计算规避、少步推理、
编译及调用调度；其中有明确拒绝的配置。CPU镜像是显存驻留管理，并不减少模型参数

### 12.2 能力与限制

较小4B在无记忆的一个初始状态上两次未生成合格完整计划，门控在动作前拒绝；
这不是覆盖全部状态的小模型baseline，因此不扩写为普遍优劣。
历史另一任务族T8也保留了程序路由证据，但不能把少量状态写成完整长程benchmark。

冷启动还受页缓存影响。本组也不证明完整任务wall time降低70%，更不等于硬实时。

## 14. 失败与负结果如何推动框架设计

| 观察 | 不能得出的结论 | 已形成的设计约束 |
|---|---|---|
| LIBERO调用少但任务wall time增加 | Agent全面提速 | 高层调用与切换单独计量，评价端到端成本 |
| 一次恢复后任务成功 | 恢复必然救回 | 分开记录建议、执行、后验确认与配对结局 |
| INT8显存低但更慢 | 所有量化都能加速 | kernel/版本进入profile，按设备重新准入 |
| 两优化组合在闭环失败 | 单项通过可任意叠加 | 每种组合独立保真与闭环门控 |
| 完成度计数不变 | 机器人一定卡住 | 持续跨度、视觉语义与检查预算联合判断 |
| 多参考图增加token仍误认 | 更多memory必然更好 | 置信度、来源、时间与对象身份约束 |
| 目标无关类型否决拦下误认，也拒绝真实目标 | 多一个Critic必然更可靠 | 同时检验假阳性、覆盖率与额外调用成本；不事后放宽准入 |
| 相同布局RGB有微差 | benchmark没有意义 | 输入trace重放 + 分块多次闭环重复 |
| reset后旧状态残留 | 模型突然能力下降 | 每环境generation与状态清理契约 |

低层动作能力、高层诊断质量和系统执行正确性是三个不同误差源。先隔离数据与包装
错误，再检查触发和语义，再看动作本身是否能完成，是当前采用的诊断顺序。
单纯增大VLM或增加重试次数，既不能解决状态污染，也可能增加误干预和等待成本。

#### 贡献一：面向VLA执行反馈的分层闭环组织

**问题：** 高层计划、低层动作完成和任务完成并不等价，直接重试容易重复无效动作或误干预。

撤销阶段确认。具体价值是使规划建议有可审计的执行边界，而不是简单在VLA前加一句提示。
**已支持：** 真实模型接口和历史受限恢复链路；LIBERO有4个救回、1个退化，但总体提升不显著。
**待补：** 新RoboDojo有效动作权限、可靠语义核验与有限干预收益，不能写已普遍提高长程成功率。
**关键对照：** 同模型、同预算的原生/只观察不干预/有限干预；报告救回、误干预和无效重试。

#### 贡献二：区分证据与假设的过程记忆及选择性规划

**问题：** 长程任务既会遗忘已经做过的操作，也会把模型误判积累成错误记忆；每步重新规划又增加成本。
**方法：** 区分观察、未验证笔记、任务确认和可信程序，保存来源与适用条件；以状态变化和
有效经验决定何时需要重新规划，避免把所有历史文本无差别塞给模型。它连接Agent能力与推理成本。
**已支持：** 历史有限LIBERO程序复用；RoboMME选择性调用相对Harness减少40.6% Planner调用、
28.1%回合耗时。后者不是“所有记忆机制整体”的独立因果消融，不能把收益全归给记忆。
**待补：** 当前两任务的记忆可靠性、错误记忆撤销与成本收益；最近6帧/12笔记本身不是算法创新。
**关键对照：** 无/有记忆及错误或过时记忆；保持VLM和动作能力相同，统计遗漏、重复执行和调用成本。

#### 贡献三：动作质量约束下的分层推理优化与部署准入

**问题：** 降低单次模型耗时、减少模型调用、降低显存是不同目标；离线输出接近也不保证任务不退化。
**方法：** 把后端能力、生效参数、相同输入动作检查、闭环质量与资源测量组成优化准入流程，
分别管理VLA计算、VLM调用及联合部署；不合格配置保留负结果并回退。
**已支持：** 旧PyTorch PI0.5分项矩阵P95 282.43→54.67ms；INT8退化被拒绝；
新4B NF4仅已证明加载显存降低。加速来自多项配置，不归功于某个单一新算法。
**待补：** 当前官方π0.5/JAX及真实VLM联合部署的端到端代价和闭环质量，尚不能声称新路径同样加速。
**关键对照：** 固定模型和输入分别改变flow步数、后端、精度或调度；分开报告冷启动、稳态与整回合耗时。

**与前期Agentic RAG-VLM的关系：** 前期工作承担可供性感知经验检索、空间约束和反思规划的
研究基础；当前三项围绕动作执行与运行成本延伸。不将前期论文成果改名重复计算为本轮新贡献。
毕业论文可以按“前期操作推理方法—VLA执行系统—高效推理与验证”组织，三者不必强称
已在同一套最终配置共同取得所有结果。

**可直接用于论文概述的表述：**

> 面向预训练VLA缺乏显式执行管理、长程过程信息易丢失以及多模型推理成本较高的问题，
> 本研究构建分层具身智能体执行框架，研究带来源和确认状态的过程记忆与选择性规划，
> 并设计动作质量约束下的分层推理优化与部署验证流程。通过任务闭环、输入重放、
> 效率消融与失败案例分别分析系统能力、运行成本及适用边界。

上述是系统/方法层面的贡献凝练，不宣称新基座模型、新量化内核、自动微调技能或所有VLA零适配。
工具调用、ReAct、记忆、编译、量化和offload均有已有研究基础；投稿创新性仍需独立文献定位。

## 附录D. 术语与研究边界

| 术语 | 在本项目中的准确含义 |
|---|---|
| VLM | 接收视觉与语言并产生语义判断/文本或结构化结果的模型 |
| VLA | 根据视觉、语言与状态生成机器人动作的策略模型 |
| Harness | 约束模型如何观察、调用工具、执行、核验与停止的外部执行框架 |
| Monitor | 高频、低成本的执行信号监测器，不是语义VLM的别名 |
| Critic / Planner | 分别偏重状态语义核验与下一步策略建议；可以共享模型但职责不同 |
| Primitive | 有明确输入、输出、执行边界的操作单元，不一定是模型或已学会技能 |
| Bounded recovery | 在次数、时间、动作和权限预算内恢复，超界不无限重试 |
| Action chunk | 一次推理生成的一段动作；生成长度与实际执行长度可不同 |
| Flow steps | 动作生成的迭代步数，不是机器人控制步数 |
| P95 | 测量样本中95百分位的时延，不是平均值或保证上界 |
| Profile | 模型/后端/精度/执行配置与其准入条件的组合 |
| SMVE | 针对明确被mask的视角规避冗余视觉计算；不是任意删相机 |
| CPU mirror | 为冻结权重保留CPU副本，降低重复GPU卸载写回成本 |
| Task memory | 当前任务进度与事件状态，不等于已验证的可迁移程序 |
| Verified procedure | 有来源、适用域和可信完成核验的符号步骤 |
| Safe stop | 软件停止发出受控动作的策略，不等于硬件安全认证 |

本报告中的旧模型和历史benchmark保留用于证据溯源，不意味着当前要重启所有路线。
当前优先事项是：核查有效动作权限与视觉核验，验证共卡部署，再做两任务有限闭环及
记忆/效率消融；不通过新增名称、堆叠模块或选择性展示结果代替验证。

## 附录I. 2026-09-23动作证据门控的失败与复现校准

[A1](../../artifacts/robomme/control_repro_calibration_20260923/VideoUnmask_ep11_A1_valid/summary.json)
与[A2](../../artifacts/robomme/control_repro_calibration_20260923/VideoUnmask_ep11_A2_valid/summary.json)
可核查。两次在同一服务重置后具有严格复现性；A1含JAX首次编译，不能与A2比较
wall time来宣称Runtime优化。这不是独立测试集的成功率样本，更不能把A1/A2当成
门控组成功。

此阶段结论是：身份门控判定本身执行正确，但**没有通过完整闭环质量门槛**；
无记忆对照在同版本同服务可复现。后续CPU请求等价测试、跨服务短程校准与新初态
配对见附录J。论文仍不能声称这项门控改善了长程成功率或Agentic与推理成本联合收益。
