# Agentic VLA：阶段性进展与路线复核

日期：2026-09-14。目标：硕士毕业研究与后续RA-L投稿。
本报告依据当前代码、冻结实验记录及技术底稿；不将设计、软件测试和机器人效果混为一谈。

## 一、阶段结论

研究主线没有改变：构建VLM/VLA协作的具身智能体系统，并优化模型推理及系统调用成本。
当前已经具备真实模型驱动的物理仿真原型、历史实验、原始视频及可复查日志。
但不能称为“框架全部完成，只剩跑实验”：当前主要瓶颈仍是可靠的语义反馈与有效动作干预。

执行方式存在需要纠正的倾向：近期较多工作集中在触发、检查、协议、失败关闭与软件回归，
而新RoboDojo路径上，稳定的Agent任务收益与记忆收益尚未建立。这些修复必要，但不能
持续以测试数量代替研究进展。下一阶段必须围绕实际任务闭环验收，不能无限加守卫和提示。

## 二、系统实际状态

| 部分 | 已具备 | 当前限制 |
|---|---|---|
| 动作模型 | RoboDojo ARX-X5上的预训练QwenPI-v3；真实RGB/本体输入及关节动作输出 | 当前不是PI0.5；默认task-only，不保证执行任意语言子任务 |
| 高层模型 | 独立Qwen3-VL-4B Planner/Critic及结构化请求、回复和预算 | 模型判断不稳定；协议合法不等于语义正确 |
| Agent执行管理 | Monitor、决策守卫、动作块重规划、有限恢复、停止权限和日志 | 最新配置尚未完整验证全部自然触发分支；不能称为通用开放技能工具箱 |
| 过程与参考记忆 | 任务台账、历史记录、对象参考与核验接口 | RoboDojo中稳定的对象身份与记忆驱动动作收益未验证 |
| 高效推理 | 参数/精度配置、编译等历史优化、模型驻留和CPU镜像切换 | 不同模型的优化不能直接互相套用；少步推理可能损伤任务能力 |
| 仿真与工程证据 | 官方RoboDojo环境、完整任务视频、reset收据、源码及配置快照 | 软件通过和链路可运行不等于成功率提升、硬实时或真机部署验证 |

真实主路径仍在XPolicyLab的StarVLA adapter中。可选FastAPI/LangGraph应用层不能直接
表述为所有机器人实验均已统一使用的部署入口。StarVLA提供模型加载接口，本项目贡献
位于其外侧的Agent管理、核验和运行时优化，不把StarVLA自身模型当作本项目训练成果。

## 三、已完成且可以汇报的证据

### 3.1 历史系统与优化结果

| 实验 | 记录结果 | 可支持的结论与边界 |
|---|---|---|
| LIBERO及PRO选定四套件，400回合/方法 | Frozen 180/400，Agentic 183/400；VLA调用减少8.4%，总回合耗时增加约16.5% | 整体成功率提升小，差异不显著；减少调用不等于端到端更快 |
| RoboMME选定8任务，80回合/方法 | Raw 23/80，Harness 36/80，Full 42/80；Full相对Harness的Planner调用减少40.6%，耗时减少28.1% | 有历史系统收益，但包含开发/扩展两部分，非统一预冻结的独立确认实验；不能直接代表当前RoboDojo代码 |
| PI0.5固定45观察推理测量 | Runtime P95 282.43→54.67 ms | 组合优化约5.17倍；包含推理步数变化、编译与无效视角消除，不是单一方法或所有任务无损加速 |
| VLM低显存候选 | Qwen3.5-4B NF4分配显存8.46→3.08 GiB，P95约1.90→2.91秒 | 有轻量化效果，但该配置更慢；不是当前Qwen3-VL-4B默认配置的量化结果 |
| RoboDojo模型切换开发测量 | CPU镜像下切换加生成P50约16.3–16.9秒→5.1–5.3秒 | 6个真实输入的测量，主要降低搬运成本，增加约17.71 GiB主机副本；不是完整任务加速70% |

P95指95%的已测请求耗时不超过该值；它不是最大时延，也不等于机器人控制频率。
这些表项有不同模型、样本和代码版本，不能拼接成一组统一闭环性能。

### 3.2 最近RoboDojo真实闭环

9月14日冻结代码的stack_bowls两个开发布局完成：1成功、1失败，75次VLA调用、
5次真实Critic调用、1次廉价动作块重规划，0次Planner恢复决策、0次有界恢复。
保存6段三相机原始视频，通过该轮reset、结果完整性与11项工程核查。

这证明该配置可以持续运行真实模型和仿真，但没有新的成功率提升证据。
9月10日其他冻结配置曾执行真实恢复与恢复后检查，但核验不确定、样本小，不能称为
已确认的自然任务救回。各轮代码不同，不能合并描述为“当前所有分支已验证”。

### 3.3 该闭环之后的修复与模型诊断

- 修复Critic强制调用没有消耗冷却、周期与事件检查重合、离线事件路由不一致等问题。
- 新增可选目标覆盖检查：物体成员数、关系和可见性不完整时，不用于积累停滞和恢复。
- 当前CPU回归1351通过、1跳过；另有3个既有收集问题文件显式排除。不同轮测试数不可相加。
- 固定7个旧视频开发帧，进行了两轮共28次真实Qwen推理。新格式第一次0/7协议接受，
  一次格式修正后4/7接受，只有2帧得到可用组数；其他未知或协议拒绝。
- 新核验未启用为默认信号；没有新机器人回合。不能把7帧反复开发说成28个独立样本，
  也不能把保守拒绝算作感知准确率提升。

## 四、当前真正的问题

### 4.1 看不清与判断不准必须分开

VLM会遗漏字段、错误描述关系；同时顶视图中嵌套物体确实可能不可见。
成功回合终帧也无法通过新的全部物体计数，说明单纯增加规则或换更大模型不一定解决。
应区分局部可见事实、跨帧过程证据和官方整任务计分，不要求模型凭单帧推断隐藏状态。

### 4.2 Agent的动作权限仍然有限

当前默认task-only保留原任务指令。Planner能够输出子目标，并不意味着底层VLA能够
可靠执行它；重试同一个任务也不等于获得了丰富工具能力。
下一步要先证实一个合法干预会影响实际动作，以及影响后是否改善局部进展。
如果这条通路不成立，应修动作适配或缩小主张，而不是继续扩跑benchmark。

### 4.3 调度修复不等于预算合理

连续调用冷却问题已修，但周期检查在真正出现异常前耗尽预算的问题尚未解决。
需要检查事件预算预留、信息是否新鲜、重复看图是否有价值及VLM调用的完整成本。
不能单纯增大预算，让更多模型调用掩盖策略低效。

### 4.4 记忆需要证明对执行有用

保存历史、给Planner提供参考和实际减少重复动作是不同层次。
RoboDojo的对象身份与可信历史利用尚无充分证据。先做回合内阶段/目标记忆，
证明信息进入决策并影响动作，再研究跨任务经验或自主技能学习。

### 4.5 高效推理需要与任务能力一起验收

PI-v3的Flow2在已有小范围闭环中表现不足，不能因为单次更快就默认部署。
目前更稳妥的起点是原生Flow4/h16，继续验证不改变动作语义的运行时与驻留优化。
同步仿真可以等待模型，因而当前时延测量还不能证明物理世界硬实时约束成立。

## 五、路线收紧与下一阶段验收

**保留两个主任务候选，不再拓展benchmark：**

- put_bottles_into_dustbin：多目标过程与效率；不由桌面清空推断全部入桶。
- build_tower：可见局部支撑、阶段进展与恢复；属于Precision，不冒称Memory任务。
- match_and_pick_from_conveyor：后续记忆专项，须先通过目标选择到动作的接口验收。
- stack_bowls：只作已有缺陷回归；不继续在同两个布局调提示后取最好结果。

**下一阶段只优先解决三项：**

1. 可用的任务反馈：复用已有多条件核验/历史/多视角接口，定义两主任务少量可见局部
   事实，在未用于调提示的观测上复核。保留未知和错误，不新增通用大而全感知系统。
2. 有效的Agent动作：选定现有合法干预，核对触发前观测、决策、真实动作差异、后验
   反馈和成本。若只有日志变化没有执行变化，判为未完成，不计Agent效果。
3. 合理的计算分配：修事件预算预留，固定原生动作配置；分别报告模型耗时、切换成本、
   VLM/VLA调用、完整任务用时及成功/失败，而不只报告单项加速。

之后按预先登记布局做小范围真实验收，再决定是否启动160回合先导对照。对照包括原生、
仅Runtime、仅Harness和Full；不因方法输赢挑任务，不修改官方成功条件或额外增加恢复步数。
后续确认样本量由先导方差与待验证效应决定，不将先导规模当作RA-L充分证据。

## 六、对毕业与RA-L目标的判断

毕业方面：已有论文成果、系统实现、真实仿真视频和优化实验可以组成研究基础；
最终是否达到学校要求需由导师与院系依据论文整体判断，不能由测试数量保证。

RA-L方面：目前不能宣布实验已充分。当前RoboDojo主线上仍需证明稳定任务收益、
有效记忆或受控成本下的能力保持，并提供对应消融与独立验证。修复可靠性是准备工作，
不是其本身就足以构成录用证据。

一句话汇报：**已建立真实可运行的Agentic VLA与推理优化原型；效率方面已有量化证据，
当前重点是把可靠的任务反馈转化为有效动作干预，并在固定任务上验证收益。**
