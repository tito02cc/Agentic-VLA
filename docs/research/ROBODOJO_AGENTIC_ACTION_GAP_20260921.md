# RoboDojo近期Agent工作与动作能力差距

核查日期：2026-09-21。用途：决定当前框架应补什么，不是追榜或替换已有结果。
结论：保留Agentic Harness + Optimize Runtime，但必须把可靠的动作纠正接口补起来。
目前的continue/reobserve/feedback_refresh不能等价于具有重抓、位姿修正工具的Agent。

**同日后续状态：** 主报告13.34已完成两轮原动作提案/FK→真实Planner→执行反馈，
但理由仍有误判；13.35随后完成52次有限能力检查，两种本地部署配置均未通过。
主计划AG已停止当前配置自主恢复扩跑。下文“尚不读取末端提案”为本次调研时的历史
状态，不是最新接口状态；工具接通不改变视觉/有效纠正仍缺证据的结论。详见
`artifacts/robodojo/bounded_capability_decision_20260921/README.md`，不再重复接入检查。

## 2. EMERGE-Policy及Harness VLA

[EMERGE-Policy原文](https://arxiv.org/html/2608.29896v1)与
[项目页](https://emerge-policy.github.io/EMERGE-Policy/)。它把规划、感知、核验、记忆分工，
使用局部恢复栈，值得借鉴失败后返回原计划的流程。但原文3.1明确LIBERO系列增加五个
Agent相机，并提高回合步数；不能解释为原传感器/原预算下的纯Agent收益。这两点不采用。
也不因多Agent命名就证明隔离上下文有效，需要同工具同观察同预算消融。

[Harness VLA/RPent审计](HARNESS_VLA_ADOPTION_AUDIT_20260828.md)已核查工具返回与记忆。
它的实质优势不只在长文本规划，还在VLA接触工具和解析移动/释放工具可组合。
LIBERO的OSC动作、深度反投影不能直接移植到当前ARX-X5 RGB/绝对关节接口。

## 3. 我们目前的差距：事实与假设分开

| 维度 | 当前源码或实验事实 | 判断 |
|---|---|---|
| 视觉判断 | 4B有明确物体关系误判；Qwen3.5-4B筛查仍不合格 | 视觉是已知短板；尚无同图Astra对照，不量化模型差距 |
| 动作权限 | 原任务VLA、短前缀刷新、观察、停止；无准入末端纠正 | 明确的结构性能力缺口，不是再写一层反思就能消除 |
| 动作理解 | Planner尚不读取经过验证的末端提案 | 不容易判断“下一段动作是否朝正确方向” |
| 记忆 | 已隔离模型猜测、保留执行回执 | 保留，但没有证明当前任务记忆增益 |
| 限制策略 | 早前以防误触发为主，工具越来越保守 | 可用于保护基线，但不能等同完整有用的纠错Agent |
| 效率 | 参考JAX任务配置未准入新的数值优化 | 先分解云/本地规划、VLA、动作提交成本，禁止拼接旧P95 |

不能只怪模型，也不能保证把模型换成Astra就成功。动作接口、观察信息与预算不同，
尚无本项目受控消融能给出每项差距的因果贡献。

## 5. 下一阶段固定顺序

1. **坐标准入**：原URDF FK与自身机器人测量一致；IK失败明确返回不可执行。
2. **运动准入**：在原场景选经原RGB确认的空闲、无接触姿态，单臂微小移动后检查实测
   跟踪误差、另一臂保持与新观测；不使用对象真值，不在抓物/接触中盲目移动。
   坐标/IK通过不代表碰撞安全，视野或接触状态不明则不准入。该阶段须另行冻结协议。
3. **动作提案审核**：原VLA提供候选，Agent选择原前缀或受限纠正；末端指令必须绑定
   当前观测与机器人坐标，工具后返回实际状态。正常路径不每块重复Planner+Critic。
4. **能力拆解**：先测试正确诊断下工具可否纠错，再同图比较强/弱视觉Planner；有人为
   指导的测试只算诊断，不计自主Agent结果。未配置云端模型时不冒充已完成Astra实验。
5. **任务验证**：organize_table保留为工具开发和长程压力任务，不无限打磨一个布局。
   工具准入后以classify_objects_by_language检验语义决策是否改变目标选择；前两任务
   有闭环证据后再用imitate_sorting_sequence隔离序列记忆。选择依据是机制，不是挑赢样本。
6. **最小完整矩阵**：每个前两任务先固定3个新case，各跑原VLA、Harness、Harness+Optimize
   共18回合。开发case单列；所有失败保留。此为可行性验证，不是RAL充分统计量。
7. **效率评价**：匹配控制步与调用上限；报告成功/分数、执行与丢弃动作、VLA/VLM调用、
   冷启动与稳态耗时、episode wall time。动作执行频率与云模型推理频率分别标注。

终止条件：正确诊断+受限工具仍无法改善时，先停扩大benchmark，归类为定位、可达性、
接触控制或任务覆盖问题。不要再用数量更多的提示/护栏代替缺失的技能。
自进化/自动微调保留后期规划，不在当前路线增加训练任务。

## 6. 具体接口设计：保留两层，不增加空转的Agent角色

下面是待准入工具的设计契约，不代表现有生产Agent已经可以调用。

### Harness：观察、提案、选择、执行、核验、记忆

- 观察：仍是原三相机、关节状态和指令；物体身份、位置关系不确定则明确标记未知。
- 提案：原VLA生成动作块；用已验证FK描述机器人末端的预计轨迹，不预测物体是否会
  被抓住，不把关节目标当实测状态。提案绑定图像/状态哈希、时间和任务上下文。
- 选择：先支持执行原提案前缀或重观察；只有运动测试通过后才开放有边界的末端纠正。
  Planner输出意图、工具和参数，host负责格式、当前状态绑定、限位和预算检查。
- 执行：返回真实执行步、实际关节反馈、未执行动作数量和停止原因；新观测后不能
  继续消费被拒绝或已失效的旧提案。工具成功返回不等于子目标成功。
- 核验：执行跟踪由本体信号判断；语义达成由观察支持的Critic判断。当前Critic仍未
  准入，故不能自动将“抓取完成”写成事实。冲突或不可判定保留，不重复同图求肯定。
- 记忆：分别保存计划目标、实际动作/回执、模型假设、核验结论及来源；临时恢复保存
  原计划返回点，避免纠错后忘记剩余步骤。只有经验证经验才可升级为可复用技能。

### Optimize Runtime：减少浪费，不用短动作块冒充加速

- 原始提案只有一个所有者和消费游标；每次选前缀记录消费/丢弃，不能并行重复下发。
- 普通路径尽量复用原VLA执行节奏，出现可解释风险/阶段切换才增加语义核验；具体
  触发频率需要对照，不预先承诺每块Planner一定比周期策略好。
- 同一观察同一问题可复用合格结果；状态、图像、目标改变立刻失效。语义不合格结果
  不可因缓存而提升可信度。
- 分开记录VLM、VLA、工具、渲染/传输、冷启动和整回合等待；记录每次模型调用的
  实际用途及是否产生被执行动作。短块可能增加总推理成本，需要用结果衡量。
- JAX数值优化/量化是独立后续变量；先保持flow10/H50参考配置，避免动作工具与模型
  数值近似同时变化，无法判断性能来源。

最关键的消融不是“多Agent名称是否更多”，而是同模型、同观察、同预算下：仅重试，
相同Planner+有效工具，加入经过验证的过程记忆，再加入运行效率优化各自改变了什么。
