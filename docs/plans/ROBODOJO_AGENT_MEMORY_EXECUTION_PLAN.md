### 一次收敛的四道门槛

1. **方法冻结前，0 GPU。** 用现有日志定位A/B差异和C不省时的主因；逐项标出哪些
   来自已有GroundSG、Harness VLA和RoboHarness，哪些是本项目实际运行代码。选一个
   具有明确输入、输出、触发条件、拒绝/退回路径的机制；决定它的最近邻对照。
   同时审计历史使用过的episode、模型权重和可用的第二个记忆相关任务族。
   若机制只能在VideoUnmaskSwap上靠专门提示或额外传感权限工作，**先停**，不发起大批次。
2. **限定一次局部改进与开发准入。** 只允许一个直接针对上述主因的设计迭代，
   不更换PI0.5、Qwen、相机、场景或评分；每组固定少量已用初态检查动作块不中断、
   决策确有变化、额外感知成本有记录。B若没有可解释的正向信号或持续产生伤害，
   暂停正式确认；C若仍几乎不触发或不节省完整成本，放弃“Agentic+Runtime联合收益”
   主张。若B在多个任务族确实有效，可单独评估Agentic主张的投稿条件；旧效率实验
   则独立用于毕业论文，**不靠换任务、改阈值、追加种子找正例**。开发集结果不进主表。
3. **冻结后才做一次确认。** 只有顶部S1过关且第二任务族/留出初态准入后，
   才预先锁定源码/权重哈希、任务族、未用初态、方法开关、顺序/预热、单回合
   超时和总GPU预算。计划上限：2个事先依据记忆需求选择的任务族，
   各20个未用于调参的初态，A/B/C共120回合；1个转移或非干扰任务族20个初态，
   A/C共40回合，核心合计160回合。若主张“结构化记忆优于同信息普通提示”或
   “选择性调度优于固定降频”，相应近邻对照是投稿必要项，事前登记所需额外回合，
   不在看成绩后补挑。第二记忆任务族、留出初态或经费不满足时，**不得把160当已批准**；
   必须先降低结论范围或更换投稿目标。这个规模是内部预算，不是RA-L官方最低要求。
4. **只分析一次并作投稿决定。** 主指标为逐任务成功率及配对净救回（救回减伤害）；
   效率为同配置的整任务GPU/墙钟时间、Planner/VLA调用、双方均成功的配对耗时、
   P50/P95、显存、记忆构建与首次请求成本。初态而非调用是独立样本，报告区间、
   所有失败/超时、消融、反例与视频。不能用提前失败造成的短回合证明加速，也不能
   用“成功率点估计相同”证明非劣。若机制差异不清、净收益不稳健或成本无收益，
   不声称双贡献RA-L就绪；保留硕士论文和技术报告成果，明确下一步需要**哪一项**证据。

**时间/算力门槛：** 先完成无GPU审计和小规模开发准入，再按实测单回合分布评估

## 1. 目标

以最少必要开发、实验和计算成本，形成可信的实验结论与可投稿论文。
不是完善所有模块，也不是完成所有历史计划。主线只有：

1. **Agentic Harness的任务价值**：规划、记忆和受约束执行如何帮助现有动作策略。
2. **Optimize Runtime的效率价值**：在明确的模型/配置及任务质量下，降低推理成本。

优先复用已有可审计成果，而不是为新平台重新开发优化算法。记忆、反思、Retry均可
介绍实际设计，但只有有实验证据的机制才写成已验证贡献。论文写作与证据整理同步，
不等待“框架全部完善”。目标是尽快完成可投稿材料，不承诺录用或用小样本替代必要证据。

**决策顺序（2026-09-23）：质量先行，效率受质量约束。** 同一任务、初态、权重和
输入协议下，先用A→B验证记忆/受约束决策是否带来可归因的任务收益，再用B→C验证
减少高层规划调用是否降低完整任务成本，且不以成功转失败或提前失败换取“加速”。
开发准入只判断链路可执行；确认批次的收益和伤害必须完整报告，不能以正例挑选任务。
本轮C只代表当前GroundSG链路的规划调用优化，不代表VLA前向、量化或硬实时已联合验证。
只有在正确子目标下仍反复出现底层动作失败，并有可用训练数据时，才另行评估小规模
技能微调；规划/记忆错误不通过换模型掩盖。若B没有可靠收益，停止以B为基础的联合收益主张；
若C仅省调用却明显损害任务质量，停止声称质量约束下的效率收益。均不自动换任务扩跑。

### 论文最低验收线：先判断够不够，再决定补什么

当前判断：框架有论文基础，不需要推倒重来；但现有工程完整性和局部正结果尚不能
自动证明有充分研究贡献或RA-L录用把握。下面是项目内部投稿检查，不是期刊官方
固定门槛，也不是毕业/录用保证。所有适用于最终主张的条件满足后停止扩张、进入投稿。

| 条件 | 最低要求 | 当前判断 |
|---|---|---|
| 问题与方法成立 | 围绕Agentic策略利用和推理成本，说明自己的决策/证据/部署机制为何必要、如何实现、何时失效；不能只罗列Planner、Memory、compile | 有骨架；具体非平凡贡献及与近邻方法的差别还需落实到实际路径，不靠改名解决 |
| 实际闭环一致 | 论文方法图、伪代码、配置和产生主结果的代码一致；规划、执行与反馈真实连通，未启用的功能明确分开 | 多条路径均有实现，但不能把通用Session、RoboMME直接runner和旧Runtime拼成一套已验证系统 |
| Agentic效果可归因 | 冻结方案在预登记、未用于调参的代表性条件上做配对；有能隔离核心机制的必要对照，报告救回和伤害 | 身份记忆小样本有支持；旧汇总混开发版本，当前确认性证据不足 |
| 效率与质量同时成立 | 复用分项效率证据，并在所声称的部署路径上报告任务质量和完整成本；若主张联合收益需同配置联合对照 | 独立效率有原始数据；完整耦合证据仍有缺口，不用新算法填充篇幅 |
| 方法价值超过堆工具 | 至少一项清楚、可检验的自主方法或系统设计贡献，有合适基线和消融；标准量化/编译不是原创，也不要求每个模块都新 | 尚不能宣布满足；先核对本地已有近邻工作和最直接基线，不重开大范围调研 |
| 论文可复查 | 主表可追溯至配置/逐例结果；成本、失败、限制和统计口径完整 | 部分具备；缺失原始来源的数字暂不作主证据 |

若不足，允许补**支撑上述条件的必要设计/局部实现**：先指出哪条条件失败，登记
最小修改和一个能够否证它的比较。已有实现能回答就不新建模块；一般工程修复不改
模型/场景/实验权限，仍需冻结版本后验证。新增模型、平台、训练或大规模矩阵须另议。
不能以“暂不扩张”为理由接受缺乏贡献的稿件，也不能以“创新不足”为理由无限加模块。
当前observe_only+身份记忆实验没有验证主动Retry、长期自进化或整个Optimize链路；
这些并非全部必做，但若保留为核心已验证贡献，就必须有相应证据，否则缩小主张。
