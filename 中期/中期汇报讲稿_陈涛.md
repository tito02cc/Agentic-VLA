## P1 硕士中期汇报

各位老师、同学好，我是陈涛。今天汇报的题目是“面向具身智能的多模态智能体系统与高效推理研究”。

我的研究主要围绕具身智能中的多模态大模型使用展开。前一阶段我主要关注视觉语言模型在机器人抓取任务中的高层推理、经验检索和失败恢复；近期我进一步将这条思路延伸到 VLA 动作生成和运行时管理，希望构建一个能够理解任务、监测执行并逐步满足部署约束的具身智能体系统。

## P2 汇报结构与研究路线

今天的汇报分为三部分。

第一部分是已有成果 Agentic RAG-VLM，这部分工作已经被 IROS 2026 录用，主要解决视觉语言模型在机器人抓取中如何利用操作经验、场景约束和失败恢复的问题。

第二部分是近期进展 Agentic VLA，也就是把前面结构化操作推理中的监测、反思和恢复思想，扩展到冻结 VLA 外层的闭环执行增强。

第三部分是后续计划，重点是继续完善闭环执行、运行时管理和实验验证。

整体来看，我的研究路线是从结构化操作推理出发，先做 Agentic RAG-VLM；然后进一步进入闭环执行增强，也就是 Agentic VLA；最后关注运行时效率优化，通过 Optimize Runtime 管理调用预算、动作复用和运行轨迹。

## P3 Agentic RAG-VLM 框架总览

这一页是我已完成并录用工作的总体框架。

Agentic RAG-VLM 的输入包括 RGB-D 图像、语言指令和目标物体信息。系统的目标不是直接训练一个新的机器人基座模型，而是在 VLM 外层加入一个 Agentic 推理流程，使模型能够利用经验、理解空间关系，并在失败后进行反思和重试。

这里说的结构化操作推理，是指把 VLM 的机器人操作决策拆成经验检索、场景约束和失败恢复几个可解释模块，而不是让模型直接给出一个黑盒式动作回答。

中间的 Agentic 外层主要包含三个部分：第一是经验检索，帮助模型找到和当前物体操作属性相近的历史经验；第二是场景图推理，把物体之间的遮挡、支撑、邻近等关系转化为可检查的抓取约束；第三是失败反思和情景记忆，在失败后不是简单重复，而是诊断原因、调整策略并保存成功经验。

最终系统输出的是结构化抓取参数，包括位置、方向、夹爪宽度、夹持力和抓取类型。这种结构化输出可以连接到机器人技能执行模块。

## P4 HAA-RAG

这一页介绍 HAA-RAG，全称是 Hierarchical Affordance-Aware Retrieval-Augmented Generation。

这里的核心问题是：视觉相似的物体，不一定应该采用相同的抓取方式。例如两个物体外观相似，但材质、脆弱度、形状稳定性不同，机器人需要的夹持力和接近方向可能完全不同。

因此，我没有只按照图像相似度检索经验，而是引入操作属性，也就是 affordance-aware 的思想。具体流程包括三步：首先通过类别筛选缩小候选经验范围；然后比较类型、材质、脆弱度和可抓取区域等操作属性；最后再结合当前图像进行视觉重排。

这样检索到的不是“看起来像”的样例，而是“对当前抓取决策有用”的历史操作经验。

## P5 Scene Graph

这一页介绍 Scene Graph，也就是场景图约束推理。

HAA-RAG 主要解决“应该参考什么经验、采用什么抓取方式”的问题，但机器人执行时还需要处理当前场景的外部空间约束。例如目标物体是否被遮挡，是否与其他物体相邻，是否支撑或包含其他物体，旁边是否存在易碎物体或碰撞风险。

在原论文中，Scene Graph 会从 VLM 的场景分析中构建有向图：节点表示物体的位置、类别、状态和脆弱度等属性，边表示 On Top Of、Contains、Occludes、Supports、Adjacent To、Behind 等空间关系。系统再从目标节点出发，检查邻域关系，推断当前抓取动作需要满足的约束。

PPT 右侧的三行对应这张图的三个层次：第一是场景图构建，对应左侧 Scene Graph Construction，也就是把物体节点和空间关系边组织成图结构；第二是约束推断，概括右侧前四个约束框，包括状态保持、碰撞避免、支撑依赖和遮挡处理，其中状态保持对应原图中的 content preservation；第三是输出抓取参数调整，对应图中最后的 Delta g Grasp Adjustment Vector，也就是把这些约束汇总成方向、夹持力和接近高度等调整量。

这些约束会进一步转化为抓取参数调整，例如改变接近方向、夹爪宽度、夹持力和接近高度。也就是说，Scene Graph 的作用不是单纯描述场景，而是把空间关系转化成可执行、可检查的操作条件。

因此，这一模块连接了视觉理解和机器人执行：前面 HAA-RAG 给出可复用经验，Scene Graph 根据当前环境修正动作约束，后面的失败恢复机制再根据执行反馈更新策略。

## P6 Self-Reflection

这一页介绍 Self-Reflection，也就是失败诊断、分级恢复和情景记忆。

在机器人任务中，失败是很常见的。如果失败后只是重新运行同一个 prompt，往往会重复犯同样的错误。所以我设计了分级重试机制。

具体来说，系统首先根据观察结果进行失败诊断。论文中把失败归纳为 14 类，并分成 pre-contact、contact、post-grasp 和 task-level 四组。诊断完成后，再进入三级恢复：第一层是调整参数，例如调整夹持力、夹爪宽度和接近高度；第二层是切换抓取类型，例如在 Power、Pinch 和 Side 这些抓取类型之间切换；第三层是重新规划，也就是在新的观察基础上生成新的方案。

同时，系统会把成功策略写入 Episodic Memory。后续遇到相似物体或相似场景时，可以检索这些经验进行复用。

这一部分的核心思想是：失败不是结束，而是下一轮推理和经验积累的输入。

## P7 研究承接：Agentic RAG-VLM 与 Agentic VLA

这一页说明我近期工作的承接关系。

Agentic RAG-VLM 主要解决的是 VLM 层面的结构化操作推理，包括操作经验检索、场景关系约束、反思和记忆。

近期的 Agentic VLA 则是在这个基础上往动作执行方向延伸。它保留 Agentic 系统中的监测、反思和恢复思想，但模型接口从 VLM 输出高层操作参数，扩展为 VLA 输出可执行的连续动作序列。

所以，两者不是割裂的两个项目。前者解决“如何让多模态模型更可靠地推理抓取策略”，后者进一步探索“如何把这种可靠性延伸到闭环动作执行和系统部署”。

## P8 Agentic VLA 总体框架

这一页是 Agentic VLA 的总体框架。

核心思想是冻结 VLA，不重新训练大模型，而是在它外层加入系统层 Harness。Frozen VLA 主要负责根据观察和指令生成连续 action chunk。

Process-Control Harness 负责观察执行状态、监测进展，并维护 memory、critic、retry 和 audit log。这里我把 Risk Monitor 和 VLM Critic 区分开：Risk Monitor 的完整含义是 Execution Risk Monitor，也就是执行风险监测器；它负责高频执行信号监测。VLM Critic 或 VLM Planner 则是低频语义判断模块。

具体来说，这里的判断可以分成两层。第一层是高频、低成本的 Execution Risk Monitor，主要根据机器人状态、动作执行进展、动作块是否过期、时延预算等信号判断是否异常。比如机器人末端长时间没有有效位移、动作块执行时间过长、或者状态反馈和预期不一致时，Risk Monitor 可以先触发重观察、动作复用终止或安全停止。第二层是低频、事件触发的 VLM Critic 或 VLM Planner，用来处理更偏语义的问题，例如是否抓错目标、当前子目标是否完成、失败后应该如何重新规划，以及是否需要重新组织语言指令。

这样设计的原因是，机器人闭环控制不能每一步都调用昂贵的大模型判断，否则会影响实时性；但完全依赖执行风险信号又很难处理语义层面的异常。所以当前框架把 VLA 作为动作生成器，把 Risk Monitor 和 Runtime 作为快速执行监督，把 VLM 高层 Agent 作为异常触发时的语义判断模块。它们共同决定当前是继续使用动作块、重新调用 VLA、触发恢复，还是安全停止。

Optimize Runtime 则负责运行时层面的调用预算管理，例如什么时候需要调用 VLA，什么时候可以复用已有动作块，以及如何记录运行过程中的状态、动作和时延信息。

因此，这一页想表达的是：我的近期工作不是直接提升 VLA 基座模型，而是在冻结模型外层构建一个可监测、可恢复、可记录的执行系统。

## P9 Optimize Runtime

这一页介绍 Optimize Runtime，也就是面向实时约束的 VLA 调用管理。

由于 VLA 推理成本较高，如果在闭环执行中每一步都调用完整模型，系统响应会变慢，也会带来不必要的计算开销。因此我设计 Runtime 模块来管理模型调用预算。

图中主要有四个机制。第一是 Low-step sampler，用较少采样步数降低单次调用成本。第二是 Call scheduler，根据执行进展判断是否真的需要昂贵的 full VLA call。第三是 Action reuse/cache，在没有异常触发时复用已有动作块，减少重复调用。第四是 Runtime metrics，重点记录 full VLA 调用次数、时延和实时超时等运行指标。成功率可以作为辅助结果，但 Runtime 本身主要回答的是系统能否减少不必要调用、降低等待时间，并在实时预算内完成动作执行。

这里的重点是：Runtime 不替代 VLA，也不改变 VLA 本身的能力，而是在执行循环中管理何时调用、何时复用、何时恢复、以及如何记录运行证据。

## P10 阶段总结与后续计划

最后做一个阶段总结。

这一页我合并为“已有成果”和“后续计划”两部分。

已有成果方面，我完成了 Agentic RAG-VLM，并且论文已经被 IROS 2026 录用。这个工作主要提出了经验检索、场景约束、反思和记忆机制。在此基础上，我近期进一步搭建了 Agentic VLA 的初步执行系统，包括冻结 VLA 接入、Risk Monitor、物理恢复、安全停止和运行轨迹记录，同时也整理了 Runtime 调度、动作复用和时延指标相关的初步工作。

后续计划方面，我会继续完善 VLM Critic / Planner 的事件触发协作，深化 Runtime 推理优化，包括调用调度、动作复用和实时超时分析，并扩大物理仿真任务和长程闭环验证。

整体来说，我希望这项研究能够让多模态模型不仅理解任务，还能在执行过程中持续监测、恢复，并逐步满足具身智能系统的部署约束。

## P12 备份页：Agentic RAG-VLM 实验验证概览

这一页作为实验验证备份页，不建议主动讲。只有当老师问到 Agentic RAG-VLM 如何验证、有没有实验设置和消融时，再使用这一页。

可以这样回答：

Agentic RAG-VLM 的实验主要用于验证方法机制。实验设置包括 12 种机器人抓取任务，每种任务测试 30 次，因此每个配置一共 360 次测试。任务覆盖单抓取、交互约束和长程清理三类场景。表格是论文中的主消融结果精简版，对比了 Full System、移除 HAA-RAG、移除 Scene Graph、移除 Recovery，以及 VLM-only。

如果需要解释表格，可以抓三点：第一，完整系统 overall success 是 78.3%；第二，移除 HAA-RAG 或只用 VLM-only 时 overall 都降到 25.0%，说明操作经验检索是基础；第三，移除 Recovery 降到 46.7%，说明失败恢复对整体稳定性影响很大；移除 Scene Graph 后 interactive 任务明显下降，说明它主要支撑空间约束任务。

这一页想说明的是：HAA-RAG 提供操作经验基础，Scene Graph 支持空间约束处理，Self-Reflection 主要提升失败恢复和长程任务稳定性。主线汇报不主动展开这页，只有被问到实验验证时再使用。

## P13 备份页：Agentic Harness 执行循环

这一页作为备份页，不建议主动讲。只有当老师问到 Agentic Harness 具体如何闭环执行时，再使用这一页。

可以这样回答：

Agentic Harness 的执行循环包括 Observe、Query、Execute、Critic、Recover 和 Verify。Observe 读取图像、状态和动作年龄；Query 在必要时向冻结 VLA 请求动作块；Execute 执行动作并监测进展；Critic 判断是否停滞、动作过期或越界；Recover 触发物理恢复、重观察和重规划；Verify 验证任务结果，如果无法恢复则安全停止。

这页主要说明 Agentic Harness 是一个执行监督和恢复框架，而不是一个新的基座模型。
